## 2. §3.C 訂正 — ‖D_θ‖ と F_θ の混同を解消

### 2.1 何が間違っていたか

第1回レポート §3.C は次の行を含んでいた:

> `‖noise_pred‖ (=‖D_θ‖) 全 k 平均 | ≈ 371.4` — `CV (変動係数) | 0.189%`

これは誤りである。コード（`mechanism_reanalysis.py`）を追跡すると、`noise_pred_norm` は
実際には次式で定義されている:

```
noise_pred_norm = ‖ε_θ‖ = ‖(x_t − D_θ(x_t,σ)) / σ‖
score_norm      = ‖ε_θ‖ / σ   (= EDM のスコア ∝ (x_t−D_θ)/σ²)
```

すなわち `noise_pred_norm` は **D_θ（デノイズ後の予測 x̂₀）そのものではなく**、
「現在のノイズ付き入力からデノイズ予測への残差を σ で割った量（ε パラメータ化のノイズ推定）」
である。

### 2.2 なぜ CV≈0.189% は測度集中の自明な帰結か（検算で確定）

`d_inferred = noise_pred_norm.mean()² ≈ 137,983`（`precond_ftheta_analysis.py` でも
`x0.numel()` から独立に確認: 同じ 137,983 — これは全体の生成潜在系列
（state_t=11 × 空間パッチ × チャンネル）の総次元数であり、DiT ブロックの隠れ次元 2048
とは別の空間であることに注意）。

x_t = x_target + σ·n （n は標準正規分布のノイズ）であり、σ が十分大きい範囲では
x_t は σ·n に支配される。D_θ による予測誤差が σ に比べて小さければ、

```
ε_θ = (x_t − D_θ)/σ ≈ n + (x_target − D_θ)/σ ≈ n
```

となり、ε_θ は「ほぼ標準正規分布ベクトル」になる。d 次元の標準正規ベクトルのノルムは
測度集中により `‖n‖ ≈ √d`、`CV(‖n‖) = std/mean ≈ 1/√(2d)` という**モデルの中身に依らない
純粋に数学的な公式**に従う。

実際に計算すると:

```
1/√(2 × 137,983) = 1/√275,966 = 1/525.3 = 0.1904%
```

報告値 CV=0.189% とほぼ完全に一致する。つまり **この 0.189% という数値はモデルが何を
学習したかとは無関係な、ε パラメータ化そのものの数学的性質**であり、旧レポートの
「std=0.701」問題と同型の測度集中トートロジーである。

### 2.3 意味のある量は F_θ（前処理前の生ネットワーク出力）

一方、`precond_ftheta_analysis.py` が独立に測定した F_θ（EDM の `c_skip`/`c_out` 前処理を
外した生のネットワーク出力）は:

| σ | ‖F_θ‖/√d | CV% |
|---|---|---|
| 80.0 | 1.5501 | 7.62% |
| 42.3 | 1.5513 | 7.61% |
| 21.0 | 1.5513 | 7.61% |
| 9.62 | 1.5505 | 7.61% |
| 4.00 | 1.5470 | 7.58% |

F_θ の CV ≈ 7.6% は、ガウス測度集中の理論下限（`1/(2√d)=0.135%` または `1/√(2d)=0.190%`、
どちらの定数を使っても桁は変わらない）の **約 40〜56 倍**であり、これは σ にも入力にも
依存しない自明な量ではなく、**状態依存の構造を持つ、モデルが実際に学習した非自明な変動**
であることを意味する。

### 2.4 訂正後の結論

- `noise_pred_norm`(=ε_θ) の CV≈0.189% は**情報量ゼロ**（ε パラメータ化の数学的必然）。
  「D_θ のノルムがほぼ一定」という旧レポートの記述は撤回し、「ε_θ のノルムがほぼ一定
  なのは EDM の ε パラメータ化に伴う測度集中の帰結であり、D_θ 自体の性質ではない」に
  訂正する。
- F_θ の CV≈7.6% が preconditioning 解析における**唯一の意味のある発見**であり、
  「ネットワークは σ に応じて出力を適切にスケールしているが、その残差には状態依存の
  非自明な構造がある」と言うにとどめる。

## 3. T8 固定入力コントロール — 新規実施

### 3.1 動機（何を検証するか）

`probe_acc_ci.json`（既存データのオフライン再確認）を精査すると、第1回レポート §3.G の
「gripper_2_phys は全層・全ステップで95%+」という記述は不正確であることが判明した。
実際のグリッド（LOEO, BH-FDR 補正済み）は次の通り:

| k \\ Blk | 0 | 4 | 9 | 13 | 18 | 22 | 27 |
|---|---|---|---|---|---|---|---|
| k=0 (σ=80, ほぼ純ノイズ) | 0.600 (n.s.) | 0.646* | 0.800* | 0.838* | **0.965*** | **0.970*** | **0.975*** |
| k=1 | 0.600 (n.s.) | 0.630* | 0.802* | 0.851* | 0.965* | 0.973* | 0.974* |
| k=2 | 0.680* | 0.744* | 0.830* | 0.867* | 0.968* | 0.973* | 0.967* |
| k=3 | 0.885* | 0.900* | 0.921* | 0.935* | 0.969* | 0.976* | 0.969* |
| k=4 | 0.955* | 0.946* | 0.958* | 0.961* | 0.974* | 0.977* | 0.976* |

(*=BH-FDR有意, n.s.=非有意。行動チャンクはまだほぼ純ノイズの k=0 でも、**深層
(Blk-18/22/27) は既に 96.5〜97.5% の精度でグリッパー状態を予測できる**。)

これはレビュー §3.1 の懸念（「Blk-0 の k=0 で95%出ているなら固定入力からの漏洩の
強い兆候」）とは逆に、**浅層 (Blk-0) はむしろ chance 水準（k=0 で 60%, 非有意）だが、
深層は k=0 から既に高精度**という、より特異的なパターンを示している。これは
「デノイジングが進むほど深層が徐々に情報を蓄積する」という単純な commitment 描像
とは整合しない。むしろ：**深層は k に関わらず、常に観測条件付け（画像/proprio）に
アクセスできる位置にあり、その情報がグリッパー状態を強く予測する**という可能性を
示唆する。T8 はこれを直接検証する統制テストである。

### 3.2 方法

新規スクリプト `t8_fixed_input_control.py` を実装した。同一の行動トークン特徴量抽出
パイプライン（`PROBE_LAYERS=[0,4,9,13,18,22,27]` の block 出力、action token 位置で
空間平均）を用い、1 回のリセットで得た観測 `obs_base` に対して以下の 4 系列を
**同一シード・同一タスク記述**で比較した:

- `baseline1`/`baseline2`: `obs_base` を全く同じ入力で2回実行（決定性の床/フロア確認）
- `img_swap`: `primary_image` のみ別エピソードの画像に差し替え（proprio/secondary/wrist/タスク記述は不変）
- `proprio_swap`: `proprio` のみ別エピソードの値に差し替え（画像/タスク記述は不変）
- `all_swap`: 画像 (primary+secondary+wrist) + proprio を全て別エピソードの値に差し替え

N=30 ペア（各ペアで独立に2つの観測をサンプル）で実行。GPU 1、5-step デノイジング。

### 3.3 結果

**決定性フロア**: `baseline1` vs `baseline2` の相対 Δfeat は全 (layer, k) で厳密に 0.000
（T1 と同様、完全な決定性を確認 — 数値的な床は存在しない）。

**k=0（σ=80、行動潜在はほぼ純ノイズ）での相対 ‖Δfeat‖**（N=30 ペア平均）:

| 変異 | Blk-0 | Blk-4 | Blk-9 | Blk-13 | Blk-18 | Blk-22 | Blk-27 |
|---|---|---|---|---|---|---|---|
| img_swap | 0.023 | 0.020 | 0.023 | 0.036 | **0.059** | 0.040 | 0.015 |
| proprio_swap | 0.009 | 0.010 | 0.022 | 0.045 | **0.082** | 0.070 | 0.022 |
| all_swap | 0.063 | 0.056 | 0.065 | 0.109 | **0.202** | 0.158 | 0.051 |

k=4（最終ステップ）でもほぼ同水準（Blk-18: img=0.046, proprio=0.063, all=0.158）——
**Δ の大きさは k=0 と k=4 でほぼ変わらない**。

行動出力レベル（gripper 次元、baseline1 との平均絶対差）:

| 変異 | gripper次元 Δ (絶対) | 全次元 L2 Δ |
|---|---|---|
| img_swap | 0.0011 | 0.074 |
| proprio_swap | 0.0015 | 0.085 |
| all_swap | 0.0018 | 0.310 |

### 3.4 解釈（T8 の判定）

**T8 は PASS（Δ≠0 を確認）**: 画像・proprio いずれの差し替えも、action-token の内部表現を
統計的に有意な水準で変化させる（決定性フロアの 0.000 に対し、全 swap 条件で明確な
非ゼロ Δ）。特に:

1. **Δ は k=0（純ノイズ入力）でも k=4（最終ステップ）とほぼ同じ大きさ**である。これは
   §3.2 のグリッド観察（深層は k=0 から既に高精度）と整合する: 深層の action-token 表現は
   デノイジングの進行とは独立に、常に条件付け情報（画像・proprio）へアクセスして
   その内容を反映している。
2. **Blk-18 が最も感度が高く**（proprio_swap で Δ=0.082 @ k=0）、これは §3.I
   自己注意解析で Blk-18 が唯一 proprio への注意を強めるサージを示した層と一致する
   （`selfattn_action_profile.png`: Blk-18 の →proprio 行正規化重みが 0.202、
   一様値の2.2倍）——独立に測定した2つの解析（アテンションパターンと条件付け感度）が
   同じ層を指し示しており、偶然の一致ではないと考えられる。
3. したがって、**§3.G の deep-layer gripper probe 高精度（k=0 でも 96-97%）は、
   「デノイジングによる行動デコードの進行」ではなく、少なくとも部分的には
   「画像・proprio 条件付けが self-attention を通じて action token に伝播している」
   ことで説明可能**であり、レビューの懸念は支持される。ただし本テストは
   「条件付けが影響する」ことを示すのみで、「gripper probe 精度の全てが条件付け由来で
   デノイジング固有の寄与がゼロ」とまでは主張できない（両者は排他的ではなく、
   条件付け経由の情報と、デノイジングが進むにつれて浅層〜中層で追加されていく情報
   （k=0→4 で Blk-0/4/9/13 の精度が明確に上昇している）の**両方が同時に効いている**
   と解釈するのが最も証拠に忠実である）。

**訂正すべき記述**: 第1回レポート「グリッパー状態は Cosmos Policy の表現全体に強く
エンコードされている」は、層依存性（浅層は k に強く依存、深層は k に依存しにくい）を
無視した過度の一般化だった。正しくは「グリッパー状態のデコードは層によって性質が
異なり、深層は条件付け経由で早期から高精度、浅層はデノイジングの進行とともに
精度が上がる」。

**決定的な発見（この解析で初めて判明）**: 上記の合計Δは全層で **-2.1pp 〜 +1.4pp** に収まり、
ブートストラップ CI の幅（±5〜6pp）の中にほぼ収まる——すなわち、**同一 run のデータ内で
PCA・分類器・n_comp を変えても、精度はほぼ動かない**。

これは第1回レポートの T6 照合表（Blk-4: +16.6pp, Blk-9: +20.6pp, Blk-13: +11.3pp）と
**全く整合しない**。原因を追跡したところ、レビューが想定していなかった**第4の交絡**が
判明した: 「旧」の数値の出典 `results/action_probe/probe_stats.json` は
**`success_rate=0.70`**、対して「新」の出典である `features.npz`（本レポートが依拠する
run）は **`success_rate=0.60`**——両者は同じ N=1108 call・50 episodes という体裁だが、
**実際には異なるロールアウト実行（run）から得られた別々の特徴量データ**である
（成功率は post-hoc の分析選択では変わらない run レベルの結果指標であり、これが
異なる以上、根本的に異なる run と判断できる）。

これを裏付ける直接証拠として、本セクションで実際に「Global PCA (n_comp=50) + Ridge」
という**旧手法の処理を新 run の特徴量に対して再現**すると（`old_report_ncomp50_ridge_global_for_reference`
フィールド）、Blk-4: 0.594, Blk-9: 0.638, Blk-13: 0.645 となり、第1回レポートが
「旧手法の結果」として報告した値（Blk-4: 0.435, Blk-9: 0.438, Blk-13: 0.569、
`probe_reconcile_02_vs_03.json` より）と 7〜20pp もの差がある。**同一の処理方法・
同一のラベル定義であっても、run が違うだけでこれだけの差が出る**——つまり第1回
レポートが「PCAリーク除去+分類器変更の効果」として報告した +11〜21pp のほぼ全ては、
**実際には比較対象が異なる2つのrunの特徴量だったことに起因する run 間変動**であり、
手法変更の効果ではなかった可能性が高い。

### 4.3 解釈

1. **レビューが指摘した逆説（「リーク除去は普通は精度を下げるはずなのに中間層は
   上がった」）は解消された**: 同一 run 内で分解すると、PCA リーク除去単独の効果は
   小さく（層により -0.7pp 〜 +3.4pp とほぼ symmetric）、系統的に「精度を上げる」
   効果ではない。逆説はそもそも「効果」ではなく、**比較していたデータそのものが
   別物だった**ことによる見かけ上の現象だった。
2. **分類器変更（Ridge→LogisticRegression）単独の効果は、全層で一貫して精度をわずかに
   下げる方向**（-0.2pp 〜 -2.5pp）。LogisticRegression への変更は「バランスの取れた
   多クラス分類器」という設計上の利点はあるが、素の精度で見れば Ridge を上回っては
   いない。
3. **設計書 §3.G が要求していた「ラベル定義差／PCA有無／run差のどれで説明できるかを
   分解した表」は、run差が支配的要因であることが判明した**ことで初めて充足された。
   第1回レポートの T6 「根本原因確定」（"Global PCA の主成分は深層表現が支配的"）
   という説明は撤回し、「run が異なるため単純比較はできず、Global-PCA由来の説明は
   支持されない」に訂正する。
4. 今後 results_02/03 のような乖離を報告する際は、**同一 run_id を明記し、run が
   異なる場合はその旨を本文冒頭で明示する**（設計書 §1.1 の要求）ことを徹底する
   必要がある。

## 5. PR の崖の切り分け + J-b 指標の置換 — 新規実施

### 5.1 動機

第1回レポートは PR が k=0-3 でほぼ平坦（Blk-4: 55.8-55.9）→ k=4 で急落（18.4）という
「崖」を報告したが、設計書 §3.D が要求する「中間 σ を挿入して崖か滑らかな関数かを
切り分ける」検証を実施していなかった。また §3.J の J-b 指標
（`‖feat(l+1)−feat(l)‖/‖feat(l)‖`）は、ブロック間の特徴ノルムの自然な成長
（Blk-0: ノルム≈16.7 → Blk-4: ノルム≈146、旧 results_01）だけでほぼ説明できてしまい、
アテンションの寄与を分離できていなかった。

### 5.2 方法

新規スクリプト `extended_step_effrank_jb.py` で1回のロールアウトから両方を解決した:

1. `num_denoising_steps_action` を 5→9 に増やし（同一 σ_max=80, σ_min=4 の
   Karras ρ スケジュールが密になる）、PR を σ の関数としてより高い分解能で追跡。
2. 各 probe block の `self_attn` モジュールに forward hook、Block 本体に
   forward_pre_hook を追加し、action token 位置で
   `‖self_attn の生出力‖ / ‖block 入力（残差）‖` を直接測定
   （設計書 §3.J の J-b 案そのもの: アテンション経路の残差ストリームへの相対寄与）。

N=25 episodes, GPU 1。

## 6. d_proxy の除去と §3.B の表現修正

### 6.1 d_proxy をCohen's dと並べることの誤り（レビュー §3.6 に対応）

`effect_size_power.py` が計算する `d_proxy = (1 − CKA_{k=3→4}) / SE_bootstrap` は、
「点推定が CKA=1.0（完全一致）から何 SE 離れているか」を表す量であり、
**Cohen's d（2群の平均差を標準偏差でスケールした効果量）とは定義も解釈も異なる**。
ブートストラップ SE は独立サンプル数（本解析では N=200 のサブサンプルブートストラップ）
に依存して縮小するため、SE が小さいほど d_proxy はいくらでも巨大な値
（Blk-4: 71.2, Blk-9: 70.2）を取り得る——これは「統計的変動を圧倒的に上回る効果」を
意味するのではなく、単に「推定が正確である」ことを示すに過ぎない。

**訂正**: 本レポートでは d_proxy を Cohen's d と並べて「効果量」として提示しない。
CKA の低下自体（Blk-4: 0.999→0.729、0-1 スケール上で 0.27 の低下）が
解釈可能な効果量であり、これをそのまま報告する。d_proxy は「この推定が統計的に
安定している」ことの確認（有意性のプロキシ）としてのみ、注記付きで残す。

### 6.2 §3.B「C2F 積極的棄却」の表現弱化（レビュー §3.5 に対応）

`effect_size_power.py` の §3.B 検出力分析は、スペクトル重心の観測傾き
`-0.00326/k-step`（4点: 0.1546→0.1669→0.1479→0.1501、非単調）に基づき
「最小検出可能傾き 0.00170 に対し観測傾きは逆方向」であることを報告し、
Spearman ρ=-0.600 (p=0.400、非有意) も別途報告している。

置換検定による範囲検定 (p<0.0001) は「k依存性がある」ことは強く支持するが、
**4点のみのデータで「積極的に逆方向」と言い切るのは、k=1→2 の1点の外れ値的な
上昇（0.167、他の3点は0.148-0.155のレンジ）に傾きが強く依存しており、
過度に踏み込んだ主張**である（レビュー §3.5 が指摘する通り）。

**訂正した結論**: 「デノイジングの精緻化が低周波→高周波の順に進む（coarse-to-fine）
という単調増加パターンは本データでは検出されない。重心は k によらずほぼ平坦
（≈0.15、白色ノイズの重心 ≈0.25 よりは低周波優位）であり、4点中1点（k=1→2）に
強く依存する非単調な変動はあるが、これを『C2F仮説への積極的な反証』と呼ぶには
根拠が弱い。」

## 7. 統合結論の書き直し（レビュー §1 に対応）

### 7.1 何が間違っていたか

第1回レポートの「統合解釈: Confidence-to-Commitment」節は、§3.A 本文が
「schednorm の単調増加は線形ガウスヌルも同様に示し、実測は最終ステップで
ヌルの48%しか変化しない」と明記していたにもかかわらず、統合部では同じ§3.Aを
「証拠1」として引用し「スケジュールでは説明不能なモデル固有の効果」と正反対の
主張の根拠にしていた。さらに統合部が引用する数値「0.192→0.266」は
レポート中のどの表にも存在しない（§3.A表の schednorm は 0.066→0.234、
§4 の Cohen's d 節は 0.0665 vs 0.2339 で内部一致しているが、0.192 はどこにもない）。

### 7.2 訂正した統合結論

生き残る頑健な発見は、性質の異なる2つに分けて報告する。

**(a) 行動出力レベル（§3.A）: Confidence-to-Commitment の素朴な形は棄却**

`‖Δx̂₀(k)‖`（schednorm 正規化後）は k=3→4 で最大（0.234）だが、同一 σ スケジュールの
線形ガウス最適デノイザ（ヌル）も同様に単調増加する（0.485 まで）。実測とヌルの比は
k=0→1 で 1.29×（超過）、k=3→4 で 0.48×（過小）——**モデルは最終ステップにおいて
線形ガウス最適推定よりも小さい変化しか起こしておらず**、「後半ほど大きく変化する」
という素朴な commitment 描像の直接的な証拠にはならない。むしろ「行動分布が
低次元多様体に集中しているため、最終ステップの真の変化は線形理論の予測より
小さい」ことを示唆する。

**(b) 中間層の内部表現レベル（§3.D, §3.K, §5）: k=3→4 に real な表現再編がある**

中間層 (Blk-4/9/13) は k=3→4 で PR が 52-58→18-21 に急落（Cohen's d ≈1.8-1.9,
「学習済みモデル固有」— §5 ランダム初期化ヌルでは同じ急落が起きない）、CKA も
0.999→0.73 に急落する。これは (a) とは**独立の現象**であり、「行動出力の変化が
小さい」ことと「中間層の内部表現が大きく再編される」ことは矛盾しない
（出力が収束しつつある一方で、内部表現の座標系が切り替わる、という状況は
ニューラルネットではしばしば見られる）。§5 の中間σ挿入により、この「急落」は
実際には**σ≈21→4の範囲にわたる4ステップ分の連続的・滑らかな減少**であり、
5-stepスケジュールの解像度不足によって単一ステップの「崖」に見えていただけ
（離散化アーティファクト）であることを確認した。

**(c) 条件付け経由の情報（T8, 新規）**

深層 (Blk-18/22/27) の action-token 表現は、デノイジングの進行に関わらず
（k=0 のほぼ純ノイズ入力でも）画像・proprio 条件付けに対して感度が高く
（T8: 相対Δfeat 最大0.20 @ all_swap, Blk-18, k=0）、gripper 状態の高精度な
線形デコード（96-97%, k=0 でも有意）はこの経路で少なくとも部分的に説明できる。
これは (a)(b) いずれとも異なる第3の経路であり、「モデルが行動をデノイジングで
決定していく」という単一の物語ではなく、**「条件付け情報の常時利用」+
「浅層〜中層の段階的な精緻化」+「中間層の最終ステップでの表現再編」という
複数の独立した機構が重なっている**、というのがデータに忠実な描像である。

**避けるべき言い回し**: 「Confidence-to-Commitment」という単一の名称で (a)(b)(c) を
一括りにする表現は誤解を招くため使用しない。使うとしても、何を指しているかを
必ず明記する（例:「中間層表現レベルでの k=3→4 再編」)。

  そもそも異なる目的の量（§3.A は線形ガウスヌルのキャリブレーション、§3.C は
  モデルの EDM 前処理パラメータそのもの）であり、一致している必要はない。ただし
  §3.A のヌルを「モデル設計上の σ_data=0.5」ではなく「実測 std=0.443」で組んでいる
  ため、ヌルの較正がモデルの実際の前提から僅かにズレている可能性はある。
  影響は小さい（0.443 vs 0.5 で高々13%程度のスケール差）と見積もられるが、
  今回のセッションでは再較正は行っていない（既知の限界として記録）。

## 7.6 pad マスクのアテンション寄与を直接検証（レビュー §3.7 に対応、新規実施）

### 動機

第1回レポート §3.H は「DiT は cross-attention で key_padding_mask を渡さず、512トークン
全体への unmasked softmax を計算しており、実トークン(15個)への重みはわずか3%、残り97%が
pad トークンに乗る」と報告し、「それでも成功率60%を達成できるのは pad 埋め込みの寄与が
学習によって抑制されているためと推測」という一行の推測で締めていた。レビューはこれを
「striking claim なのに検証が一行の推測」と指摘し、(a) pad位置のvalueがほぼゼロで効いて
いない、(b) フックが取り逃した隠れマスクがどこかにある、のどちらであるかを
「フック再構成 attention·V とモデル実出力の直接照合」なしには確定できないとした。

### 方法（コード調査 → チェックポイント検証 → 実データ数値照合の3段階）

1. **コード調査**: `minimal_v4_dit.py` の `Attention` クラスを読むと、
   `self.attn_op = DotProductAttention(..., attn_mask_type="no_mask")` で cross-attention
   バックエンドが明示的に「マスクなし」設定されている（第1回レポートの主張どおり、
   フックが見落とした隠れマスクは存在しない）。さらに T5 埋め込み計算コード
   (`get_t5_emb.py::encode_prompts`) は実配列長を超える位置を
   `encoded_text[b][lengths[b]:] = 0` で明示的にゼロ埋めしてからキャッシュしており、
   かつ `k_proj`/`v_proj` は `bias=False`（RMSNorm(0)=0 なので `k_norm` を通しても
   ゼロのまま）。これは数式上、**pad位置の K・V が厳密に 0 になる**ことを意味する。
2. **実データでの直接確認（新規、GPU不要）**: 実際に使用中の
   `robocasa_t5_embeddings.pkl` を直接ロードし、pad 位置(実トークン数を超える範囲)の
   埋め込みノルムを確認 → **厳密に 0.0**（サンプル例: 13トークンの実文で、14番目以降の
   512-13=499 位置全てノルム0.0）。
3. **チェックポイントでの直接確認（新規、GPU不要）**: 実際にロードされる学習済み
   チェックポイント (`Cosmos-Policy-RoboCasa-Predict2-2B.pt`) の state_dict キーを確認 →
   `cross_attn.{q,k,v,output}_proj` に `.bias` パラメータは一切存在しない
   （コード上の `bias=False` が実チェックポイントにも反映されていることを確認）。
4. **フック再構成 attention·V とモデル実出力の直接数値照合（新規実施、レビューが要求した検証そのもの）**:
   `t_pad_attn_verify.py` を新規実装。7 probe layers × 5 denoising steps × 15 calls
   (N=525 records) で、cross_attn の `compute_qkv` から Q,K,V を捕捉し、
   `attn_op`（マスクなし softmax の実際の計算ノード）に forward hook を張って
   **モデルが実際に計算した生の attn·V 出力（output_proj 適用前）**を直接捕捉。
   同じ Q,K,V から手動で `softmax(QKᵀ/√d)·V` を再構成し、実出力側と数値照合。
   さらに出力を real-token(0..n_real-1) 由来項と pad-token(n_real..511) 由来項に
   線形分解して両者のノルムを個別に測定した。

### 結果

**フック再構成 vs モデル実出力の一致度**: `max|reconstruction − real_output| = 4.89×10⁻⁴`
（bf16 丸め相当、T1/T2 の合否基準 1e-4 とほぼ同水準）→ **フックは実際のモデル計算を
正しく再現しており、隠れマスクは存在しない**ことが実データでも確認された（懸念(b)の解消）。

**pad由来の出力寄与（層別、N=525 records、`pad_attn_verify.json`）**:

| Layer | 実トークンへの重み | pad への重み | 出力ノルム(real由来項) | 出力ノルム(pad由来項) |
|---|---|---|---|---|
| Blk-0  | 0.027 | 0.973 | 0.0118 | **0.000000** |
| Blk-4  | 0.040 | 0.960 | 0.0183 | **0.000000** |
| Blk-9  | 0.025 | 0.975 | 0.0079 | **0.000000** |
| Blk-13 | 0.022 | 0.978 | 0.0106 | **0.000000** |
| Blk-18 | 0.065 | 0.935 | 0.0458 | **0.000000** |
| Blk-22 | 0.038 | 0.962 | 0.0270 | **0.000000** |
| Blk-27 | 0.064 | 0.936 | 0.4580 | **0.000000** |

全層で pad 由来の出力ノルムは厳密に 0.000000（丸め誤差の範囲内ですらなく、文字通りゼロ）。
実トークンへの注意重みは全層で2-7%程度に過ぎない（第1回レポートの「3%」と整合）が、
**出力の100%は実トークン由来項で説明できる**。

### 解釈（合否判定）

- **懸念(a)「pad位置のvalueがほぼゼロで効いていない」→ 確認（正確には「ほぼゼロ」ではなく
  厳密にゼロ）**。T5 埋め込みが pad位置を明示的にゼロ埋めし、`v_proj` が bias なし
  線形層であるため、V_pad は数学的に厳密に 0 になる。これは学習で獲得された性質
  （「学習によって抑制されている」という第1回レポートの推測）ではなく、
  **アーキテクチャ上の設計（T5埋め込みのゼロパディング＋bias無し線形層）による必然**である。
- **懸念(b)「フックが見落とした隠れマスクがある」→ 否定**。`attn_mask_type="no_mask"`
  という明示的なアーキテクチャ設定に加え、フック再構成が実モデル出力とbf16精度で
  一致することを実データで確認した。隠れマスクは存在しない。
- **結論**: 第1回レポートの「モデルはcross-attentionでマスクを適用しない」という主張
  自体は事実として正しかったが、「それでも動作するのは学習で pad 寄与が抑制されている
  ため」という説明は誤り（というより不要な推測）だった。正しい説明は
  「**pad位置のK・Vはアーキテクチャ上厳密にゼロになるため、softmax確率質量の
  ほとんどがpadに乗っても出力には数学的に全く影響しない**」であり、これは
  トレーニング結果に依存しない、モデル構造から導かれる保証である。
  一見 striking に見えた「97%がpadに乗る」という観測は、**cross-attention出力の
  健全性に対する脅威ではなく、単に無駄な（しかし無害な）softmax確率質量の分配**
  であったと結論づけられる。

## 8. 今回のセッションで対応しきれなかった項目・既知の限界

- レビュー §4（run 混在・provenance の run_id 明記）について、本レポートが依拠する
  T8/T6/extended-step は全て今回新規に実行した単一の run であり、それぞれ独立した
  `results/{t8_fixed_input, t6_decompose, extended_step_effrank_jb}/` に成果物を
  保存しているが、既存の §3.A-K（第1回レポート）の run とは別 run である点に注意
  （比較する場合は run 間比較として扱うこと）。
- T8・T6・extended-step のいずれも単一タスク (PnPCounterToCab)・単一シード系列
  であり、複数シードでの再現性確認（設計書 §4 「複数シード」要件）は未実施。
- **新たに判明した限界（§5 のデバッグ過程で発見）**: action-token 特徴量の
  Participation Ratio は、call 数よりも**サンプリングした episode（=シーン）数**に
  強く依存する（2 episodes→PR≈2, 3 episodes→PR≈2, 25 episodes→PR≈4, 既存の
  50-episode run→PR≈55）。すなわち **PR の絶対値は「何種類のキッチンシーンを
  サンプルしたか」に強く左右される、母集団の真のPRを直接には表さない量**であり、
  この限界は第1回レポートの PR 解析（§3.D, §5 ランダム初期化比較を含む）にも
  遡って適用される。今後 PR を報告する際は、**使用した episode 数を必ず明記し、
  episode 数を増やした場合の PR の感度（学習曲線）を確認する**ことを推奨する
  （本セッションでは時間の制約上、この感度分析自体は実施していない）。
