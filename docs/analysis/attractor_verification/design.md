# Cosmos Policy スキルアトラクタ解析：検証設計＋実装手順

**位置づけ**: `attractor_eval.md` の提案（スキルアトラクタの遷移・数・時空間特徴の解析）を、これまでの検証アーク（results_01〜04 / v1〜v3）で確立した方法論的規律の上に再設計したもの。
**中心の問い**:
- Q1: Cosmos Policy は推論時にどのようにスキル／アトラクタを遷移するか
- Q2: いくつのスキルに遷移し、特定スキルを推論時に活性化できるか
- Q3: 各スキルアトラクタはどのような時空間的特徴を持つか

**設計の基本姿勢**: 提案は「線形分離可能なスキルアトラクタが存在する」を**前提**にしているが、本設計ではそれを**検証すべき仮説**として扱い、**反証を試みる**。アークの最大の教訓（もっともらしい数値ほど未検証、クラスタは往々にしてシーン由来）を全面に据える。

## 1. 用語の操作的定義と「3つの時間軸」の交通整理（最重要）

提案は「拡散過程に沿った遷移」と「アクション系列に沿った遷移」の2軸としているが、Cosmos Policy には**3つの独立な時間的軸**があり、混同すると解析が破綻する。まずこれを固定する。

| 記号 | 軸 | 範囲 | 意味 | 何を捉えるか |
|---|---|---|---|---|
| **k** | デノイジングステップ | 0..K-1（K=5 or 9） | 1回の推論内のノイズ除去 | アトラクタ**基盤への収束**（basin） |
| **τ** | アクションチャンク内位置 | 0..H-1（H=32） | 予測した行動系列の各タイムステップ | チャンク内の**フェーズ境界** |
| **t** | ロールアウト時刻（policy call） | エピソード内のcall番号 | 実際にタスクを進める時間 | タスク遂行中の**スキル/フェーズ遷移** |

提案の「拡散過程の軌跡」= **k軸**、「時間軸の軌跡」= **τ軸**（チャンク内）。だが「AをしてからBをする」というスキル遷移が実際に起きるのは主に **t軸**（call を跨ぐ）である。**3軸を別々に解析し、図表でも決して混ぜない**。

**「スキル」の操作的定義（単一タスクの制約への対応）**:
本モデルの既存解析はすべて PnPCounterToCab（pick-place 単一タスク）。この設定に「把持/前進/旋回」のような**異種スキルは存在しない**。存在するのは pick-place の**サブフェーズ**（reach → approach → grasp → lift → transport → align → place → release）である。したがって:
- **レベル1（フェーズ）**: 単一タスク内のサブフェーズ。t/τ軸の遷移解析はこのレベル。
- **レベル2（スキル）**: 真に異種のスキルを扱うには、**複数のRoboCasaタスク**（PnPCounterToCab, OpenDoor, TurnLever, CloseDrawer 等）を回し、タスク横断でアトラクタを比較する必要がある。「いくつのスキルか」「特定スキルを活性化」という問い（Q2）は**マルチタスク収集を前提に初めて意味を持つ**。
- **本設計は最初からマルチタスクで収集する**（§4）。単一タスクに閉じるとQ2は「フェーズ数の推定」に縮退する旨を明記する。

**「アトラクタ」の操作的定義（提案より厳密に）**:
「重心（centroid）」だけでは静的な塊にすぎない。**動的なアトラクタ**として次を要求する:
- (定義A・収束) 条件付け（シーン+言語+現在状態）を固定し、初期ノイズ seed のみを変えて N サンプル引いたとき、k が進むにつれ最終表現が**低分散の同一領域へ収束**する。
- (定義B・引力圏) その領域の近傍から出発した表現が、1ステップのデノイジングで領域**中心へ向かう**（スコア場が sink を持つ）。
アトラクタと呼ぶには A（収束）を最低条件とし、B（引力圏）を強い証拠とする。**単なるクラスタ（静的な塊）とアトラクタ（動的な sink）を区別する**。

## 2. 中心的リスク：「スキルクラスタ」ではなく「シーンクラスタ」を見る問題

**これが本解析の成否を分ける最大の交絡**。アークで確立した通り、action-token 表現の分散の大部分は**キッチンシーン/エピソードの違い**に由来する（PRがシーン数に強依存）。したがって、生の潜在に DP-GMM / k-means / HDBSCAN を素朴にかければ、**発見されるクラスタは高確率で「スキル」ではなく「シーン」または「エピソード」**である。

**統制策（すべてのクラスタリング系解析に必須）**:
1. **シーン内クラスタリング**: 同一シーン（同一エピソードの reset 直後の固定レイアウト）内で、フェーズが進む間の表現を集め、シーンを跨がずにクラスタを推定する。これで「シーン差」を除去。
2. **シーン残差化**: 各エピソードの平均を引く（`Z - Z̄_episode`）、またはエピソードIDを共変量として回帰で除去した残差に対してクラスタリング。
3. **シーンシャッフルnull（P5）**: 「フェーズ情報を壊し、シーン構造だけ残したnull」を作り、実データのクラスタ数・分離度がnullを**有意に超える**ときのみ「スキル/フェーズ由来のクラスタ」と主張する。
4. **クラスタ↔シーンID / クラスタ↔フェーズ の相互情報量**を必ず報告。クラスタがシーンIDと高MI・フェーズと低MIなら、それは**シーンクラスタであってスキルではない**と結論する。

この統制を通らないクラスタリング結果は、Q2の「スキル数」として採用しない。

## 3. 3つの問い → 仮説と反証条件

| 問い | 仮説 H | 反証条件（これが観測されたら H を棄却） |
|---|---|---|
| Q1-basin (k軸) | 条件付け固定で seed を変えると、k とともに x̂₀ 分散が収束する（アトラクタ基盤） | seed 間分散が k で減らない／複数モードに割れず単一点に潰れるだけ（＝条件付けが決定的で「引力圏」構造がない） |
| Q1-transition (t軸) | ロールアウト中、表現は少数のフェーズ状態を離散的に遷移し、境界で滞在が短い | 表現が連続的にドリフトし離散状態・境界が同定できない／遷移がシーン切替と一致（＝スキルでなくシーン） |
| Q2-count | シーン統制後、フェーズ/スキルに対応する K 個の安定クラスタが（複数手法・複数seedで一致して）存在 | クラスタ数が手法・seed で不安定／シーンシャッフルnullを超えない／クラスタがシーンIDとのみ高MI |
| Q2-activate | 早期kでの steering で、条件付けと異なる**ターゲットスキルが行動として発現**する（dose-response あり） | 行動が変わらない／ランダム方向steeringと区別できない／潜在は動くが行動は不変（＝潜在アトラクタは行動に対して因果を持たない） |
| Q3-spatial | 各アトラクタは分離した凸的領域で、固有の形状・局所次元を持つ | 領域が重なり分離不能／局所次元がシーン分散に支配され意味を持たない |
| Q3-temporal | 各アトラクタは特定の τ/フェーズで活性化し、遷移が鋭い（エントロピーピークが狭い） | 活性が τ/フェーズと無相関／遷移が滑らかで境界を定義できない |

**「言えない」も結論である**: 反証条件が満たされたら、それを積極的に報告する（例：「Cosmos Policy の潜在にスキルアトラクタは同定できず、観測されたクラスタ構造はシーン由来だった」も価値ある結論）。

## 4. 表現基盤とデータ収集プロトコル

### 4.1 マルチタスク収集（Q2を意味あるものにする）
- タスク集合 𝒯 = {PnPCounterToCab, OpenDoor, TurnLever, CloseDrawer, …}（RoboCasa で利用可能な 4〜8 タスク）。
- 各タスク N_ep エピソード（≥25、シーン多様性のため）、closed-loop ロールアウト、**call毎に seed 変化（P1）**。
- 成功/失敗を記録（成功trajectoryのみ／全trajの両方を保持し、解析で選べるように）。
- **シード3系列**で全収集を反復（P2、multi-seed）。

### 4.2 表現の捕捉（軸を潰さない）
既存の `feature_analysis.py` は action-token を**空間平均**しており τ を失う。アトラクタ遷移(τ軸)には**τ解像度が必要**。捕捉を2種類に分ける:

| 捕捉 | 内容 | 用途 |
|---|---|---|
| **Z_pool[k, layer]** | action-token 空間平均 2048-dim（既存互換） | k/t軸の basin・クラスタ・steering |
| **Z_tau[k, layer, τ]** | チャンク内 τ を保持した per-token 表現 | τ軸のフェーズ境界・within-chunk遷移 |
| **X̂₀[k, τ, dim]** | 予測行動チャンク 32×7（解釈可能な行動空間） | 行動レベルの basin・vector field・DTW |

- 層は既存の PROBE_LAYERS=[0,4,9,13,18,22,27]。**主対象は中間層(4/9/13)**（アークで構造が確認された層）と**行動空間 X̂₀**（解釈可能）。深層(27, PR≈2)は「出力収束」であってスキル分離ではない可能性が高いので補助的に。
- 全捕捉に run_id・seed・task・episode_label・phase_label（後述）・SHA256 を付す（P2/P8）。

### 4.3 フェーズ・ラベル（弱教師、循環回避）
LDA/教師ありには**行動由来のフェーズラベル**が要る。潜在から作らない（循環回避）:
- **グリッパー状態**（`robot0_gripper_qpos`）と**エンドエフェクタの運動**（接近中/把持中/搬送中/解放）を**シミュレータの物理量**から導出してフェーズを付与。
- 把持イベント（接触＋グリッパー閉）・解放イベントで区切る。これは潜在と独立なので、潜在の分離をこのラベルで評価しても循環しない。
- 注意（アークの教訓）：グリッパー信号は低エントロピー＆条件付けパススルーで自明に分離しうる。**グリッパー単独をスキル定義に使わない**。フェーズは運動＋接触＋グリッパーの複合で定義する。

## 5. Q1：遷移のダイナミクス（3軸を分離して）

### 5.A basin 収束（k軸）— アトラクタの核心テスト
`confirm_seed_rootcause.py`（v3で作った「同一観測・seedのみ変える」実験）を**アトラクタ測定に転用**する。
- 手順: 1つの固定条件付け（あるフェーズにいる1観測）に対し、seed を変えて M（≥64）サンプルの x̂₀(k) と Z_pool(k) を生成。
- 指標: 各 k で seed 間分散 `Var_seed[x̂₀(k)]`、および最終 x̂₀(4) の**モード数**（後述クラスタリング）。
- **アトラクタなら**: 分散が k とともに減少（basin へ収束）。単一点なら1モード、多義なら数モードに収束。
- **ヌル(P5)**: 条件付けをランダム化した場合の分散推移。実測が条件付けにより有意に速く収束するか。
- 複数フェーズ・複数タスクで反復し、「収束先の identity がフェーズ/タスクと対応するか」を確認。

### 5.B デノイジング流れ / ベクトル場（k軸、提案B）
- 行動空間 X̂₀ または LDA 2〜3次元で、格子点に潜在を置き、**固定σ・固定条件付け**で1ステップのスコア（`D_θ − x`方向）を評価し quiver plot。
- **注意**: ベクトル場は σ と条件付けを固定したときのみ意味を持つ。σ を跨いだ矢印を混ぜない。sink（アトラクタ）と ridge（境界）を同定。
- あくまで可視化＋sink位置の定量（sink座標 vs centroid の一致）に用いる。

### 5.C ロールアウト遷移（t軸）— スキル/フェーズ遷移の本丸
- 各 call の Z_pool（k=最終）をエピソードに沿って並べ、時系列として解析。
- **変化点検知**（`ruptures`, PELT）：`‖z_t − z_{t-1}‖` および分布変化から遷移時刻を検出。
- **Sticky HDP-HMM**：状態数を自動推定しつつ滞在しやすさを入れて系列をセグメント。ただし**入力はシーン残差化した Z**（§2）でなければシーン遷移を拾う。
- 出力: 遷移確率行列、平均滞在時間、状態↔フェーズラベルのMI。
- **ヌル**: シーンシャッフル系列で同じHMMを回し、状態数・遷移構造が実データで有意に構造的か。
- **判定**: 検出された状態が**行動フェーズと高MI**かつ**シーンIDと低MI**のときのみ「スキル/フェーズ遷移」と認める。

### 5.D within-chunk 遷移（τ軸）
- Z_tau または X̂₀ の τ 方向で、単一チャンク内にフェーズ境界（例：把持の瞬間）が含まれるかを変化点検知。
- グリッパー切替を含む call（アークで把握済み）で境界が τ 内に現れるか。

### 5.E 条件付けの guidance 強度（提案③）
- 「別スキル/別フェーズの典型的 x_T」を初期ノイズに使い（seedを別スキルの basin から引く）、正しいアトラクタへの収束が**何ステップ遅れるか / 失敗するか**を測る。
- 条件付け（言語/画像）の引力 vs 初期ノイズの引力の綱引きを定量。§6の steering の前段としても機能。

## 6. Q2：スキル数の推定 と 特定スキルの活性化（介入）

### 6.1 スキル数 K の推定（教師なしバッテリ＋シーン統制）
提案の手法群を**単独では信用せず、バッテリ＋一致＋null超過**で採用する。

- 前処理: PCA で分散90〜95%保持（**標準化方式は固定・明記**、P3）。UMAP等の非線形は定量には使わない（可視化のみ）。
- 手法バッテリ（§2の統制下で実行）:
  - DP-GMM（空間的、K自動）
  - HDBSCAN（密度、遷移点をノイズ分離）
  - k-means + シルエット/エルボー（ベースライン）
  - スペクトラル eigengap（k近傍グラフのラプラシアン固有値ギャップ）
- **採用基準**: (a) ≥3手法で K が一致、(b) **シーンシャッフルnullのK分布を有意に超える**、(c) クラスタがフェーズ/タスクと高MI・シーンIDと低MI、(d) **3 seed で K が安定**。これを全て満たして初めて「モデルは K 個のスキル/フェーズアトラクタを形成」と言える。
- レベル1（フェーズ、単一タスク内・シーン内）とレベル2（スキル、タスク横断）で別々に K を推定。

### 6.2 特定スキルの活性化（Activation Steering）— 因果テスト
最も強い因果検証。アークの規律（P6/P7）を厳守。

**steering ベクトルの抽出（循環回避）**:
- `v_steer = μ_target − μ_source`（重心差）または ターゲット分類の線形SVM法線。
- **v の推定に使うデータと、steering をテストするデータ／観測は分離**（held-out）。同じデータで v を作り「重心に着地」を確認するのは循環（P6）。

**介入**:
- `h ← h + α·v_steer` を、**早期k（最初の20〜50%ステップ）**の選択層に加算（提案A、拡散の構造決定はデノイジング前半という知見に整合）。
- α を 0 から掃引（dose-response）。
- **フックのT1確認（P7）**: α=0 で出力が無介入と max\|Δ\|=0 で一致することを確認（steeringフックが観測経路を汚さない保証）。

**必須コントロール**:
- (c1) **ランダム方向**（v と同ノルムの無作為ベクトル）: 効果が方向特異的か。
- (c2) **シーン直交化 v**: v から「シーンIDで予測できる成分」を除去した版。効果がスキル方向由来かシーン漏れか。
- (c3) α=0（no-op）。

**検証（定義した空間の外で、P6）**:
1. **行動レベル（主）**: steered action をシミュレータで実行し、**ターゲットスキルの発現率**（Intervention Success Rate）と**元スキルの成功率低下**を測る。これが本命の因果証拠。
2. **独立プローブ**: 無介入データで学習したスキル分類器が steered 表現をターゲットと判定するか。
3. **DTW**: steered ロールアウトと**規範的ターゲットスキル軌道**の DTW 距離が α とともに縮むか。
4. **競合観察（提案）**: 視覚は source（掴むべき物がある）＋介入は target（移動）のとき、綺麗に別スキルを実行するか／フリーズ・破綻するか。綺麗に切り替われば「潜在アトラクタが言語/画像より行動決定に強い因果」を示す。

**dose-response の解釈**: α↑で target 発現率が単調↑・source 成功率が単調↓、かつランダム方向(c1)では起きない——これが揃って初めて「特定スキルを活性化できる」と言える。潜在が動くのに行動が動かないなら「アトラクタは行動に対して因果を持たない」と結論（反証）。

## 7. Q3：各アトラクタの時空間特徴

各同定アトラクタ i について:

**空間的特徴**:
- centroid μ_i、共分散 Σ_i（等方 vs 異方）、**局所次元**（basin内 local PR、ただしシーン分散を残差化した上で）。
- **basin 幅**: μ_i から方向 d に摂動して、なお i に収束する最大 α（引力圏の広さ）。§6の steering 掃引で測れる。
- **分離度**: μ_i 間距離 / Σ の広がり（Fisher比）、線形分離可能性（held-out 線形分類精度 vs シーンnull）。

**時間的特徴**:
- **活性 τ/フェーズ**: 各 i が主にどの τ 位置・どのロールアウトフェーズで最大確率になるか（スキル活性化ヒートマップ、提案C。横軸τ or t、縦軸クラスタ、色＝所属確率）。
- **滞在時間**（t軸）: HMM の平均 dwell。
- **収束速度**（k軸）: basin へ入るまでのデノイジングステップ数（§5.A の分散半減 k）。
- **遷移のシャープネス**: 所属確率エントロピー `−Σp_i log p_i` の**ピーク幅**（提案②）＋ 相空間速度 `‖z_{t+1}−z_t‖` のピーク。狭い＝キレの良い切替。**ヌル**（シャッフル）比で有意な鋭さか。

## 10. 統計枠組み（P5）

- 独立単位は **episode**（callではない）。クラスタブートストラップでCI。
- 遷移・分離・収束は permutation（episode単位シャッフル）で p 値化、**BH-FDR**で多重補正。
- steering は α に対する用量反応の傾き＋CI、ランダム方向との差を検定。
- 効果量（Cohen's d / Fisher比 / MI）を併記。**「差なし」主張には検出力（最小検出可能効果）を明記**。
- **3 seed** で主要指標（K、遷移行列、steering ISR）を再現し seed 間分散を報告。

## 11. 実行順序とゲート

```
[0] マルチタスク収集（call毎seed, 3系列, τ解像度）+ manifest    ── A1,A2 pass 必須
      │
[1] フェーズラベル付与（物理量から, 潜在非依存）
      │
[2] 線形分離可能性の予備検証: フェーズをシーンnull超で線形分離できるか
      │  ──不可なら──▶ 「線形分離アトラクタ」前提を棄却、設計を記述解析に切替
      │可
[3] スキル数K推定（バッテリ+シーン統制+null+seed安定, §6.1）  ── A3,A4 pass 必須
      │
[4] 遷移ダイナミクス（§5: basin/rollout/τ）
      │
[5] Q3 時空間特徴（§7）
      │
[6] steering 因果テスト（§6.2, 行動検証）  ── A1(α=0),A5 pass 必須
      │
[7] ヌル対比・FDR・multi-seed 集約 → 信頼度付き主張リスト
```

**ゲート [2] が決定的**: フェーズがシーンnullを超えて線形分離できないなら、「線形分離可能なスキルアトラクタ」という提案の大前提が本モデルでは成り立たないということ。その場合は無理にクラスタリングを進めず、**「アトラクタは同定できなかった」を結論**として記述解析に切り替える（P5/§3の姿勢）。

## 13. 反証条件と「言える／言えない」の線引き

| 結論として言える | 条件 |
|---|---|
| 「モデルは K 個のスキル/フェーズアトラクタを持つ」 | §6.1 の (a)(b)(c)(d) 全充足＋3 seed 安定 |
| 「推論時に特定スキルを活性化できる」 | §6.2 で行動レベル ISR が α と用量反応・ランダム方向で起きない・多seed再現 |
| 「アトラクタは basin 構造を持つ」 | §5.A で条件付け固定・seed掃引の分散収束が null 超 |
| **言えない/棄却として報告すべき** | ゲート[2]不通過／クラスタがシーン由来（A3 fail）／潜在は動くが行動不変（steering反証）／K がseed不安定 |

**単一タスクに閉じた場合の限界を明記**: Q2の「スキル数」は「pick-place のフェーズ数」に縮退し、真の異種スキル間の遷移・活性化はマルチタスク収集を経ないと言えない。

## 14. 想定される失敗モードと事前の備え（正直な章）

アークの経験から、以下は**高確率で起こる**。事前に備える。

1. **クラスタ＝シーン**（最有力の失敗）。→ §2の統制とA3で早期検出。フェーズMI<シーンMIなら潔く「シーンを見ている」と報告。
2. **深層(Blk-27, PR≈2)の"少数アトラクタ"が実は出力収束**。→ スキル分離ではなく行動の低次元化。中間層・行動空間を主対象にし、深層は補助。
3. **グリッパーで自明分離**。→ フェーズを運動＋接触の複合で定義、グリッパー単独をスキルにしない。
4. **steering が潜在は動かすが行動は動かさない**。→ これは反証であって失敗ではない（「潜在アトラクタは行動に対して因果を持たない」＝重要な発見）。行動検証(P6)を主指標にしているので正しく捕まる。
5. **PCA標準化方式で K が変わる**（v3の20pp教訓）。→ 方式固定＋両方式で K の頑健性を付記（A6）。
6. **seed規律違反で basin/クラスタが偽収束**（seedバグ再来）。→ A2で常時監視。
7. **単一runの偶然**。→ 3 seed 必須。Tier A（多seed生存）に達したもののみ強く主張。

**要約**: 本設計は提案の可視化・定量・介入の枠組みを採用しつつ、(1) 3つの時間軸の分離、(2) シーン交絡の統制（最重要）、(3) 単一タスク制約の明示とマルチタスク化、(4) steering の行動レベル因果検証、(5) アークで確立した seed/PCA/run/null の全規律、を組み込んだ。**前提を検証し、反証を許す**構えにしてある——「アトラクタは同定できなかった」も正当な結論として出力できる設計である。
