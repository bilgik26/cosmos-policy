# Cosmos Policy 感覚運動結合動態検証：実行結果レポート

## 0. 本レポートについて

本レポートは `docs/analysis/latent_dynamics_verification_design.md`（以下「設計書」）が指示する
検証——言語プロンプトに依存せず、感覚と運動の結合動態（Dynamics）を一次的対象として埋め込み、
その空間上のエネルギー場・ベクトル場に基づく動的介入によってアクションが駆動できるか——を実行した
結果をまとめる。設計書は現象学・エナクティヴィズムの立場から、「状態（Observation/Latent）」と
「行動（Action）」を分離して扱う表象主義的アプローチを破棄し、感覚運動の結合動態の系列自体を
数学的対象として扱うことを要求している。

本検証は `docs/analysis/verification_report_v3.md` と `docs/analysis/attractor_verification_report.md`
（以下、先行2検証）が確立した基盤（モデル・データ収集・プローブ層・統計手法・循環性回避の原則）を
そのまま踏襲し、その上に構築した。先行2検証で判明していた核心的事実——(1) 潜在空間には離散的な
スキルアトラクタは存在せず低次元の連続的な進行多様体が存在する（attractor_verification_report.md
§5.3-5.4）、(2) 静的なmid-layer steering（固定ベクトルの一律加算）は特定スキルを誘発できず、
むしろ大振幅・後期スケジュールでタスク遂行そのものを方向特異的に破壊するだけだった
（同 §10.1-10.3）——を出発点とし、「状態への静的な摂動」ではなく「フロー（速度場）への動的な介入」
であれば異なる結果が得られるかを検定した。

先行2検証と同じく、**「前提を検証し反証を許す」姿勢**を貫く。実装中に発見したバグは隠さず
第7節にまとめ、結果は都合の良い部分だけを取り上げず正直に報告する。

## 1. 実験設定と検証基盤

### 1.1 環境・モデル・データ

**実行環境**: Singularity不使用（`.venv`直接アクティベート、`uv`管理のPython 3.10）、GPU1
（RTX 4090、`CUDA_VISIBLE_DEVICES=1`）。シミュレータはRoboCasa（robosuiteベース、PandaMobile
ロボット）、GPUレンダリングはEGLヘッドレス（`MUJOCO_GL=egl`）。

**モデル**: `nvidia/Cosmos-Policy-RoboCasa-Predict2-2B`（28ブロックDiT、EDM拡散フレームワーク、
`num_denoising_steps_action=5`、σ = 80.0 → 42.3 → 21.0 → 9.6 → 4.0）。プローブ層はBlk-13
（先行検証で一貫して主対象とされた中間層、7層[0,4,9,13,18,22,27]のうちの1つ）。1回の推論
（1 policy call）は行動チャンク（32 timesteps×7次元）を生成し、`num_open_loop_steps=16`分だけ
環境に適用してから次のcallを行うclosed-loopロールアウトである。

**対象タスク**: `PnPCounterToCab`（カウンターからキャビネットへの物体のpick-and-place）。
先行検証のsteering因果テスト（attractor_verification_report.md §10）が一貫してこのタスクのみを
対象としていたことに倣い、本検証も同タスクに絞った（他タスクへの一般化は§9参照）。

**データ**: 先行検証が収集した2種のデータセットをそのまま流用する。

| データ | 内容 | 本検証での用途 |
|---|---|---|
| `collect/`（元データ、`_phases.npz`付き） | 4タスク×2 seed系列×20 episode、フェーズラベル付き、`episode_success`なし | フェーズ3のC3条件（静的steeringベクトル`v_steer`の計算、`steering_intervention.py`の`compute_steering_vectors()`を再利用） |
| `collect_v2/`（`episode_success`修正版再収集） | 同上、per-episode成功フラグ付き | フェーズ1・2（D空間構築、エネルギー場推定）、フェーズ4（教師軌跡） |

新規のGPUロールアウト収集は行わず、フェーズ1・2は完全にオフライン（GPU不要）でこれら既存データを
再利用する。フェーズ3のみ新規GPUロールアウトを実行する。

### 1.2 本検証で新たに用いるデータ

`collect_v2/`のnpzには、先行検証（§5.6/§5.7）が使ったBlk-13の action-token 特徴量
（`feat_k4_layer13`など）に加え、物理量として `gripper_qpos`（2次元）・`eef_pos`（3次元）・
`eef_quat`（4次元）がcall単位で保存されている。本検証のフェーズ1はこれらの物理量を
「行動が環境に及ぼした効果」の代理指標として新規に利用する（詳細は§2）。

### 1.3 検証フェーズの全体構成

設計書は4フェーズからなる（本レポートの章立てはこれにそのまま対応する）。各フェーズの成果物は
次のフェーズの入力になる。

```
[フェーズ1] 感覚運動結合動態の空間埋め込み（D空間構築、オフライン）
      │  遅延座標埋め込みでZ_t系列をD_tに写像
      ▼
[フェーズ2] 場（Field）とエネルギー構造の定義（オフライン）
      │  D空間上にKDEエネルギー場を推定、§5.7 DMD解析をD空間で再評価
      ▼
[フェーズ3] 「不変量」への動的介入（Dynamic Steering）によるアクション駆動（オンライン、GPU）
      │  ダミープロンプト下でVector Field Steeringを実施
      ▼
[フェーズ4] 評価指標の設定
         動的因果効力・多様体逸脱度・感覚フィードバック従属性を測定
```

## 2. フェーズ1：感覚運動結合動態の空間埋め込み（D空間構築）

### 2.0 要旨

設計書は、静的な潜在表現 `Z_t` 単体ではなく、時間窓 `τ` の系列 `S_t=[Z_t-τ,…,Z_t,…,Z_t+τ]`
を遅延座標埋め込み（Takens' delay embedding）で単一の動態ベクトル `D_t` に写像する空間 `𝒟`
の構築を要求する。本実装は、これを先行検証の進行多様体 `X_p`（PCA(10)、scene残差化後のBlk-13特徴）
の上に構築し、`X_p` のフロー（速度）と、行動が環境に及ぼした効果の物理的代理指標（エンドエフェクタ
速度・グリッパー開閉速度）を結合したベクトルの遅延窓を線形PCAで低次元空間へ圧縮した。

**主な結果**: 4タスク中2タスク（PnPCounterToCab, TurnOnStove）で、D空間上でも§5.6/§5.7と同じ
「成功エピソードのみで学習した進行度参照分布からの逸脱量」検定を再現でき、成功/失敗の分離は
D空間・元の`X_p`空間の双方で統計的に非常に強く（Mann-Whitney `p<10^-4`、完全分離）支持された。
ただし分離の相対的な鋭さ（正規化逸脱マージン）はタスク依存で、PnPCounterToCabでは`X_p`の方が
D空間よりも分離が鋭く、TurnOnStoveでは逆にD空間の方が鋭かった——結合動態表現が常に元の進行多様体
より「良い」表現になるとは一概には言えない、というのが正直な結論である。D空間の内在次元数は
相関次元で1.4〜2.7と、`X_p`と同程度に低次元である。**実装過程で2件の重大なバグ（スケール混合、
非因果的リーク）を発見・修正した（詳細は§7）**。

### 2.1 目的

先行検証（attractor_verification_report.md §5.4-5.6）は、静的な潜在表現 `Z_t` を主対象として扱い、
「表現」と「その時間微分（フロー）」を別々の対象として分析していた（§5.3で軌跡の滑らかさを、
§5.7でDMDによりフローのヤコビアン固有値を別個に検定するなど）。設計書の中心的主張は、これらを
「観測（ハサミという物体特徴）」と「行動（切るという運動）」の分離という表象主義的切断の一種と
みなし、両者を最初から不可分な一つの動態的対象として埋め込むことで、これまで見えなかった構造
（特に成功/失敗の予兆や、力学的不安定性とエネルギー場の対応）がより明確に取り出せるかを検証する
ことにある。本フェーズはその埋め込み空間 `𝒟` 自体を構築し、少なくとも先行検証が確立した
「進行多様体」としての基本性質（低次元性、成功/失敗の分離可能性）を引き継いでいるかを確認する。

### 2.2 手法

**2.2.1 結合ベクトルの構成**。各task（2 seed系列プール、`collect_v2/`）について、
scene残差化 `X_r = X - X_bar_episode` 後の特徴を標準化・PCA(10次元)に還元し、
先行検証（§5.6/§5.7）と同一の進行多様体 `X_p ∈ ℝ^10` を得る。各call `t` について
以下を計算する:

```
c_t = [ X_p,t (10dim),  V_t = X_p,t - X_p,t-1 (10dim),
        Δeef_t = eef_t - eef_t-1 (3dim),  Δgrip_t = w_t - w_t-1 (1dim) ]  ∈ ℝ^24
```

ここで `w_t = |q^(0)_t| + |q^(1)_t|` はグリッパー開き幅（2指のqposの絶対値和、
`phase_labeling.py`で確立された符号相殺対策と同じ定義）である。`V_t`・`Δeef_t`・
`Δgrip_t` はいずれも **backward difference**（`t` 対 `t-1`）である。エピソード先頭
（`t=0`）は `t-1` が存在しないため全て0で埋める。

各成分の物理的スケールが大きく異なる（`X_p, V` はPCAスコア単位でスケール〜O(5〜20)、`Δ`eef
はメートル単位でスケール〜O(0.01)）ため、`c_t` をtask内で標準化してから次のステップに進む
（この標準化を怠ると何が起きるかは§7バグ#1参照）。

**2.2.2 遅延座標埋め込み**。各エピソード内で、backward窓 `τ=3` の

```
S_t = [ c_t-2, c_t-1, c_t ]  ∈ ℝ^72
```

（エピソード先頭で `τ` 未満の履歴しかない場合は最古の `c` を繰り返してpaddingする）を構成し、
task内でプールした `S_t` 全体に線形PCA（`D_dim ≤ 8`）を学習してエンコーダとする
（設計書§2実装指示3「線形PCA、または自己符号化器」の線形PCA版。非線形自己符号化器は§9参照）。

**2.2.3 backward-only窓を採用した理由**。設計書の式は未来 `Z_t+τ` を含む対称窓だが、
フェーズ3（推論時オンラインsteering）はこの同じ埋め込み関数をロールアウト実行中にリアルタイムで
呼び出す必要があり、未来のZは原理的に参照できない。フェーズ1・3で同一の埋め込み関数を使うことを
優先し、意図的に対称窓ではなくbackward-only窓を採用した（設計書からの意図的逸脱、§9で開示）。

**2.2.4 妥当性検証の手法**。(a) D空間で§5.6と同一の「進行度5分位ビン参照分布（成功エピソードの
みで学習、GroupKFold(group=episode)でheld-out）からの逸脱量」検定をそのまま再実行し、
元の `X_p` 空間の結果と比較する。逸脱量は
`dev(x) = √( Σ_d (x_d - μ_b,d)^2 / σ^2_b,d )`
（`b`はその点の進行度ビン、`μ_b,σ^2_b` は縮小推定分散、`success_failure_trajectory_test.py`
の実装をそのまま再利用）で定義される正規化ユークリッド距離である。Mann-Whitney U検定
（片側、成功<失敗）でエピソード単位の平均逸脱量を比較する——この検定は分布形状に関する仮定を
置かない順位検定であり、逸脱量の分布が正規分布に従う保証がない本設定に適している。
(b) D空間の内在次元数を簡易的に2手法（PCA累積寄与率90%到達成分数、相関次元のlog-logスケーリング
勾配）で確認する（§5.4の4手法バッテリーの縮小版、§9で開示）。(c) 2次元PCA可視化。

**Mann-Whitney検定の飽和に関する注記**: 成功/失敗の逸脱量分布が完全に非重複（重なりなし）の場合、
U統計量は群サイズのみで決まる最大値に達し、p値はそれ以上小さくならない「天井効果」が生じる。
この場合、元の `X_p` 空間とD空間の逸脱量の実際の値が異なっていても、p値は完全に一致しうる（実際に
本検証で発生した、§7バグ#2参照）。この天井効果下でも空間同士を比較できるよう、正規化逸脱マージン
`(min(dev_fail) - max(dev_succ)) / std(dev_succ)`
を追加の効果量として報告する。

### 2.3 結果

| タスク | n成功/n失敗 | エンコーダ説明分散比 | D空間: 逸脱p値 | D空間: 正規化マージン | `X_p`空間: 正規化マージン | fail/succ逸脱比(D) | D空間内在次元(相関次元, fit R²) |
|---|---|---|---|---|---|---|---|
| PnPCounterToCab | 18/22 | 0.552 | **3.91×10⁻⁸** | 6.86 | **11.80** | 2.34 | 2.66 (0.9998) |
| TurnOnStove | 15/25 | 0.528 | **8.63×10⁻⁸** | **5.82** | 3.02 | 2.31 | 1.63 (0.988) |
| CloseDrawer | 40/0 | 0.640 | 検定不可（失敗0） | — | — | — | 2.24 (0.9996) |
| CoffeePressButton | 39/1 | 0.723 | 検定不可（失敗1、閾値3未満） | — | — | — | 1.42 (0.896) |

（CloseDrawer・CoffeePressButtonは§5.6/§5.7と同じ理由——失敗episodeが3未満——でこの検定を実施
できない。これは検定の限界であり、当該2タスクが「良くない」ことを意味しない。）

PnPCounterToCabのseed系列別内訳: seed195（n成功9/n失敗11）`p=9.85×10^-5`、seed196
（n成功9/n失敗11）`p=9.85×10^-5`（プール後より緩いのはサンプル数減少による）。
TurnOnStoveのseed系列別内訳: seed195（7/13）`p=1.29×10^-5`、seed196（8/12）
`p=7.94×10^-6`。2seed系列とも同方向・同オーダーで一貫しており、単一seedの偶然ではない。

D空間の内在次元数（相関次元、log-logフィットR²=0.90〜1.00と良好）は1.4（CoffeePressButton）〜
2.7（PnPCounterToCab）で、PCA累積寄与率90%到達には（許容した上限である）8成分全てを要する
（`n90_variance=8`が全task共通——これは「90%に到達するのに8次元必要」というより「エンコーダの
出力次元をそもそも8に制限しているため、90%基準そのものが天井に張り付いている」ことを意味する
測定上のアーチファクトである。相関次元の方が informative）。

### 2.4 解釈

- **D空間は元の進行多様体 `X_p` が持っていた「成功/失敗の分離可能性」を壊さずに保持している**
  ——2タスクとも Mann-Whitney `p<10^-4` で完全分離という、§5.6の元の結果と定性的に同じ強さの
  分離が再現された。これは結合動態表現が退化していない（情報を失って分離能力を落としていない）
  ことの最低限の確認である。
- **しかし「結合動態表現の方が優れている」という単純な主張はできない**——正規化逸脱マージンで
  比較すると、PnPCounterToCabでは `X_p` 空間（11.80）がD空間（6.86）より明確に鋭く分離しており、
  TurnOnStoveでは逆にD空間（5.82）が `X_p` 空間（3.02）より鋭い。2タスク中1タスクずつで逆方向
  という結果は、「感覚運動を結合した表現の方が常に情報量が多い」という設計書の暗黙の期待を
  単純には支持しない。1つの解釈は、TurnOnStove（ボタン操作、eef速度・グリッパー変化が比較的
  单純な動作）ではeef/gripperの物理的delta情報が付加的な弁別力を持つが、PnPCounterToCab
  （pick-and-place、複数フェーズにわたる複雑な動作）では72次元への窓拡張とその後の8次元への
  圧縮自体が情報の希釈（各tau-sliceが24/72しか専有できない）を招いている可能性である——ただし
  この解釈は本検証の範囲では確証されていない。
- **D空間もまた低次元**（相関次元1.4〜2.7）であり、§5.4の「実質一桁台前半次元」という知見と
  整合する。感覚運動を結合しても、力学の本質的自由度は増えていない——これは「ハサミと切る動態は
  不可分な低次元の構造を持つ」という設計書の仮説と、少なくとも次元数の観点では矛盾しない。

### 2.5 結論

感覚運動結合動態の空間埋め込み（D空間）は、先行検証が確立した進行多様体の基本的性質（低次元性、
成功/失敗の統計的分離可能性）を壊さずに構築できた。ただし、結合動態表現が単体の潜在表現より
「優れている」かはタスク依存であり、一般的な優越性は確認されなかった。

### 2.6 注意点・限界

1. **視覚特徴の勾配（attention mapの時間微分）は未捕捉**のため結合テンソルから省略した
   （attractor_verification_report.md §1.7と同種のスコープ制約）。
2. **生成行動チャンク `X_hat_0`（32×7の実際の行動出力）も未捕捉**のため、eef_pos/gripper_qpos
   という環境物理量の差分で代替した——これは「行動出力の変化」そのものではなく「行動が環境に
   及ぼした効果」であり、design.mdの式とは正確には一致しない代理指標である。
3. エンコーダは線形PCAのみで、非線形自己符号化器は未実施。
4. プーリング単位はタスク（2 seed系列結合）とし、タスクをまたいだプーリングは行っていない
   （§7バグ#1参照、これは設計判断であり不具合ではない）。
5. 内在次元数の評価は§5.4の4手法バッテリーではなく簡易2指標版（PCA累積寄与率・相関次元）に
   縮小している。

### 2.7 今後の検証案

- 非線形自己符号化器（オートエンコーダ、変分オートエンコーダ等）によるD空間構築との比較。
- `X_hat_0`（生成行動チャンク）を実際に捕捉した上での「真の行動変化」を用いた結合ベクトルの
  再構成。
- §5.4と同じ4手法バッテリーによる内在次元数の厳密な再評価。

## 3. フェーズ2：エネルギー場とベクトル場の推定

### 3.0 要旨

D空間上に、データ密度に基づくエネルギー関数 `E(D) = -log p(D)` とそのベクトル場（スコア）
`∇_D log p(D)` を推定した。設計書が要求する「score matchingの技術の流用」に対応するため、
解析的Gaussian KDEスコアとdenoising score matching（DSM）MLPの2つの独立推定器を実装し、
既知の合成分布（2成分等方ガウス混合）上で両者が真のスコアと平均コサイン類似度0.93/0.96で一致する
ことを事前に確認した上で、以後の全解析には近似誤差のない解析的KDE版を用いた。

**主な結果**: 検証可能な2タスク（PnPCounterToCab, TurnOnStove）で、成功エピソード（held-out）の
エネルギーは失敗エピソードよりも一貫して低く（Mann-Whitney `p<10^-6`）、「成功軌跡はエネルギーの
谷、失敗軌跡はより高いエネルギー領域」という設計書の仮説を支持した。さらに§5.7のDMDヤコビアン
解析をD空間で再評価したところ、**PnPCounterToCabで元の`X_p`空間では反証されていた
「成功=自己安定化・失敗=不安定化」パターンが、D空間では統計的に有意な形で復活した**
（`X_p`空間: `p=0.38`〜`0.59`、非有意 → D空間: `p=0.023`）——これは感覚運動を結合した表現が、
元の表現では見えなかった力学的構造を可視化しうることを示唆する新規の知見である。一方、
「局所的な力学的不安定性（DMD `|λ_max|`）とエネルギーの直接対応」は弱い/有意でない
負の相関にとどまり（`ρ=-0.06`〜`-0.12`）、設計書が期待した「不安定領域=高エネルギー領域」と
いう単純な対応は、少なくとも窓単位の粒度では確認されなかった。

### 3.1 目的

設計書フェーズ2は、フェーズ1で構築した空間の上に「データ多様体に引き込むベクトル場」を推定し、
§5.7（DMDヤコビアン解析）で確認された「幾何学的逸脱」と「力学的不安定性」の対応をこの新しい
空間で再評価することを要求する。§5.7は元の `X_p` 空間で、この対応が**タスク依存**であること
（TurnOnStoveでは明確に支持、PnPCounterToCabでは明確に反証）を発見していた。本フェーズは、
感覚運動を結合したD空間で同じ解析を行った場合、この対応がより一貫した形で現れるか、あるいは
元の非一貫性がそのまま残るかを検証する。

### 3.2 手法

**3.2.1 解析的Gaussian KDE場**。標準化後の空間で等方ガウスカーネル・Scott則帯域幅
`h = N^-1/(d+4)`（`N`: サンプル数、`d`: 次元数）を用いたKDE

```
p(x) ∝ (1/N) Σ_i=1..N exp( -‖x - x_i‖^2 / (2h^2) )
```

の対数密度と、その解析的勾配（スコア）`∇_x log p(x)` を実装した。KDEは近似誤差のない
閉形式の勾配が得られる利点があり、本検証のデータ規模（task毎N〜500〜1000点）では十分安定に
推定できる。

**3.2.2 Denoising Score Matching (DSM) MLP**。Vincent (2011) の一致性定理により、ガウスノイズ
`σ` で汚染したデータ `x+n` から `-n/σ^2` を予測するように学習したネットワークは、
`σ→ 0` の極限で対象分布のスコア `∇_x log p(x)` に収束する（NCSN型拡散モデルの
スコア関数推定と同じ原理）。これがdesign.mdの「score matchingの技術を流用」の直接的実装である。
8段階の幾何等比ノイズスケジュール（`σ ∈ [0.05, 1.5]`）でMLP（2隠れ層、128ユニット、SiLU）
を学習し、`σ^2` 重み付きlossで訓練した。

**3.2.3 合成データでの事前検証**。2成分等方ガウス混合（`μ_1=(-2,0)`, `μ_2=(2,0)`,
`σ=0.7`、N=1500）を生成し、解析的に導出可能な真のスコア関数と比較した。KDE・DSM双方が
真のスコアと平均コサイン類似度0.8を超えることを合格基準とし、実データに適用する前に
`synthetic_validation()`内でassertする設計とした（`dmd_jacobian_stability_test.py`の
`synthetic_dmd_validation()`と同じ、本プロジェクトで確立された「新手法は既知の正解を持つ合成
データで先に検証する」慣行に倣う）。

**3.2.4 成功のみでのKDE学習と循環回避**。§5.6/§5.7と同じ循環回避原則——「失敗は基準から逸脱する」
という主張を検定するのに、その基準自体を失敗データから作ってはいけない——に従い、KDEは
**成功エピソードのみ**で学習する。成功エピソード自身のheld-outエネルギーはGroupKFold
(group=episode)で測定し、失敗エピソードには全成功エピソードで学習した最終KDEを適用する
（失敗エピソードは学習に一切使われない）。

**3.2.5 §5.7 DMD解析のD空間での再評価**。`dmd_jacobian_stability_test.py`のwindowed DMD
（窓幅8、SVD階数打ち切り: 累積エネルギー90%・上限4、§5.7と同一設定）をD空間の軌跡にそのまま
再適用する。各窓の `|λ_max|` と、窓終端callにおけるエネルギー `E(D)` の対応を
Spearman相関で検定する。

### 3.3 結果

**合成データ検証**: KDEスコアと真のスコアの平均コサイン類似度 = **0.932**、DSM-MLPスコアと
真のスコアの平均コサイン類似度 = **0.964**、KDE-DSM間の一致度 = **0.934**。いずれも合格基準
0.8を明確に上回り、両推定器が正しく機能することを確認した。

**成功/失敗のエネルギー分離**:

| タスク | n成功/n失敗 | エネルギー平均(成功,held-out) | エネルギー平均(失敗) | Mann-Whitney p(成功<失敗) |
|---|---|---|---|---|
| PnPCounterToCab | 18/22 | 7.948 | 14.465 | **3.91×10⁻⁸** |
| TurnOnStove | 15/25 | 7.137 | 12.647 | **8.63×10⁻⁸** |

**§5.7 DMD解析のD空間再評価**（窓幅8、CloseDrawer/CoffeePressButtonは§5.6/§5.7と同じ理由で
検定不可）:

| タスク | n窓 | エピソード内max\|λ\| MW p(成功<失敗) | 1.0超え到達率(成功/失敗) | Fisher p | λ_max〜エネルギー Spearman ρ (p) |
|---|---|---|---|---|---|
| PnPCounterToCab | 697 | **0.0228** | 13/18, 22/22 | **0.0130** | −0.121 (p=0.0013) |
| TurnOnStove | 662 | **8.55×10⁻⁸** | 0/15, 25/25 | **2.49×10⁻¹¹** | −0.063 (p=0.104、非有意) |

（比較: 元の`X_p`空間での§5.7結果は PnPCounterToCab: MW `p=0.38`〜`0.59`（非有意）、
TurnOnStove: MW `p<0.0001`（有意）——TurnOnStoveは両空間で一貫して有意、PnPCounterToCabは
`X_p`空間で非有意だったのがD空間で有意に転じた。）

### 3.4 解釈

- **成功=低エネルギー、失敗=高エネルギーという設計書の中心仮説は、検定可能な2タスク全てで明確に
  支持された**（`p<10^-6`、失敗の平均エネルギーは成功の約1.8〜2倍）。ただし、この結果は
  §5.6の「進行度参照分布からの逸脱量」検定（§2.3で再現済み）と本質的に同じ情報を別の定式化
  （マハラノビス距離的な逸脱 vs. カーネル密度）で測定しているに過ぎない可能性が高く、
  「エネルギー場」という新しい概念装置が真に付加的な情報を提供しているかは、この結果単体からは
  判定できない（§3.6の限界参照）。
- **§5.7のDMD解析をD空間で再評価した結果は、本検証全体で最も新規性の高い知見である**:
  元の `X_p` 空間ではPnPCounterToCabの「自己安定化/不安定化」パターンは明確に反証されていた
  （成功・失敗どちらのエピソードも同程度に`|λ|>1`へ到達し、群間で有意差なし）。ところが
  **感覚運動を結合したD空間で同じ解析を行うと、このパターンが `p=0.0228` で有意になった**
  （1.0超え到達率も成功13/18 vs 失敗22/22で分離を示す）。これは「潜在表現単体では見えなかった
  力学的シグナルが、行動の物理的効果（eef/gripper delta）を結合することで顕在化した」という、
  設計書の中心的仮説——「観測と行動を分離すると本来の構造が見えなくなる」——と整合する具体的な
  肯定例である。**ただし1タスクのみでの観測であり、過大な一般化はしない**（TurnOnStoveは元々
  両空間で有意だったため「D空間だから改善した」という証拠にはならない）。
- **一方、より細かい粒度（窓単位）でのDMD不安定性とエネルギーの直接対応は支持されなかった**——
  Spearman `ρ` は2タスクとも弱い負の値（−0.06〜−0.12）で、PnPCounterToCabではこの弱い相関が
  統計的に有意（`p=0.0013`、n=697と大きいため小さな効果量でも検出される）だが、符号が
  「不安定なほど低エネルギー」という**直感に反する方向**である。TurnOnStoveでは非有意
  （`p=0.104`）。「局所的な力学的不安定性が生じている瞬間は、必ずしもその瞬間の密度が低い
  （エネルギーが高い）わけではない」——これは、力学的不安定性（ある窓の近傍がどう発散するか）
  と静的な密度（その一点がどれだけ典型的か）が、原理的に異なる量を測っていることを考えれば
  驚くことではない。**設計書§フェーズ2実装指示2「不安定な窓の終端でエネルギーの谷が形成され
  失敗軌跡はリッジを越えて発散する」という素朴な期待は、少なくとも窓単位の粒度では支持されない**
  ——これはエピソード単位の集計（成功=低エネルギー・失敗=高エネルギー）とは矛盾しない
  （エピソード全体としては失敗の方が高エネルギー領域を通るが、その中の「不安定化が起きた
  まさにその瞬間」がエネルギーの谷から最も離れているとは限らない、という、より繊細な描像を
  示唆する）。

### 3.5 結論

D空間上のエネルギー場は、§5.6の逸脱量検定と整合する形で「成功=谷、失敗=高エネルギー」という
大局的パターンを支持した。より新規性の高い発見は、§5.7のDMD解析をD空間で再評価すると
PnPCounterToCabの力学的不安定性シグナルが（元の`X_p`空間では見えなかったにもかかわらず）
統計的に有意になったことである。一方、窓単位の細かい粒度でのDMD不安定性とエネルギーの直接対応は
支持されず、むしろ弱い逆相関を示した——「幾何学的な逸脱・力学的不安定性・局所エネルギー」の
3つは、大局的には整合するが瞬間瞬間では必ずしも一致しない、複数の独立した(しかし関連する)量
であるというのが、より正確な描像である。

### 3.6 注意点・限界

1. エネルギーの成功/失敗分離が§5.6の逸脱量検定と情報的に重複している可能性があり、「密度に
   基づくエネルギー場」という定式化が真に新しい情報を提供しているかは本検証だけでは判定できない。
2. KDEは等方ガウスカーネル・単一帯域幅（Scott則）の簡便な推定であり、真の密度の非等方構造を
   捉えきれていない可能性がある。
3. DSM-MLPは合成データでのみ厳密検証しており、実データでは解析的KDEとの定性一致確認のみに
   とどめた。
4. §5.7と同じくCloseDrawer・CoffeePressButtonは失敗episode不足のため検定不可。
5. 窓幅8・階数上限4という設計は§5.7からの継承であり、D空間に対して再チューニングしていない。

### 3.7 今後の検証案

- エネルギーと逸脱量検定の情報的重複を定量化する（例えば逸脱量を制御変数とした偏相関）。
- DMD不安定性とエネルギーの負の相関という意外な結果について、窓幅を変えた頑健性チェック。
- 非等方カーネル（対角/full共分散）でのKDE再推定。

## 4. フェーズ3：推論時Vector Field Steering（動的介入）

### 4.0 要旨

先行検証（attractor_verification_report.md §10）のsteering因果テストは、固定ベクトルの静的な
一律加算（mid-layer steering）を用いていた。設計書は、この介入が「状態」に対する静的な摂動で
あったために力学系の多様体から直交方向に状態を弾き飛ばした（タスク破壊のみに終わった）と解釈し、
代わりに「フロー（ベクトル場）」への動的介入——推論時の各stepで、現在位置に応じて成功エピソードの
局所的な「次に何が起きたか」へ潜在表現の速度ベクトルを書き換え、多様体の接平面へ射影する——を
実装するよう要求する。本フェーズはこれをオンラインのclosed-loopロールアウト中に実装し、言語
プロンプトを無効化（ダミー文に置換）した状態でタスク関連の行動が自律的に誘発されるかを検証した。

**主な結果**: ダミープロンプト下でのタスク完遂は、動的フィールドsteering・静的steering・
ランダム方向介入のいずれでも一切誘発されなかった（6条件×8episode中、実プロンプト基準
（success_rate=0.50、先行検証と完全一致）以外は全て**0.00**）。フックの実効注入量は典型特徴norm
の13%強と無視できない大きさであり、T1（no-op確認）も正しく機能していたため、この結果は実装の
不備ではなく否定的知見として受け止める。ただし、ダミープロンプト単体（steeringなし）が既に
success_rateの床（0.00）に達していたため、動的介入と静的介入・ランダム介入との違いをsuccess_rate
だけでは判別できない——フェーズ4（§5）はこれをより細かい粒度の指標で補完する。

### 4.1 目的

「プロンプトが無くても、特定の感覚入力に対してエネルギー場の谷を人工的に深くする（＝ベクトル場
介入）ことで、モデルが勝手にその感覚運動ループ（行為）に引き込まれる現象」（設計書§3）が観測
されるかを検定する、本検証で唯一の**因果**検証である。先行検証のsteering実験（§10.1-10.4）と
同じく、これは「潜在空間の操作が行動レベルの因果を持つか」という、相関ではなく介入による検証
であり、design.mdが批判する「静的な状態摂動」の限界を「動的なフロー摂動」で克服できるかを問う。

### 4.2 手法

**4.2.1 オンライン因果推定の設計とオフラインとの違い**。フェーズ1のD空間はbackward-only（因果的）
窓で設計済みだが、offline構築時の scene残差化 `X_r = X - X_bar_episode` は
「そのエピソード全体の平均」という、ロールアウト実行中には知り得ない非因果的な統計量に依存
していた。オンラインでは以下の**因果的な代替**を用いる:

- scene残差化の代わりに、そのエピソードのcall 0からこのcallまでの**累積平均**を引く
  「running mean residualization」を使う（call 0は自明に0になる）。
- `V_t`・`Δeef_t`・`Δgrip_t` は元々§2のバグ修正でbackward difference
  （`t` 対 `t-1`）に直してあるため、そのままオンラインで使える。
- 窓padding規則もフェーズ1の`build_delay_embedding_input`と完全に同一のものをオンラインで再現
  する（最古の`c_t`を繰り返す）。

**4.2.2 「対象の動態的不変量」の定義とオフライン/オンラインの非対称性**。フェーズ2で成功
エピソードのみからD空間上の(位置, 次に何が起きたか)ペアを「フローライブラリ」として構築する。
ここで設計上重要な非対称性がある: オフラインのライブラリ点は完結したエピソードであり、**未来**
（forward difference `X_p,t+1-X_p,t`）を教師信号として安全に使える。一方オンラインのクエリ点
（現在ロールアウト中のエピソード）はその未来を原理的に持たない。したがって:

```
v_target(D_t) = Σ_i∈kNN(D_t) w_i・(X_p,i+1 - X_p,i)

  where  w_i = exp(-‖D_t - D_i‖^2 / 2h^2) / Σ_j exp(-‖D_t - D_j‖^2 / 2h^2)
```

とする（`k=15`、`h`=k近傍距離の中央値、ライブラリ点は成功エピソードのみ・カーネル重み付き平均、
`energy_field_test.py`の`X_p`フロー——§2で導入した backward `V_t`——とは異なり、ここでは
ライブラリ側は forward differenceを使う設計判断であることに注意）。

**4.2.3 多様体接平面への射影**。設計書§フェーズ3実装指示2「多様体（進行多様体）の接平面への
射影を必ず行い、逸脱（＝失敗）を防ぐ」に従い、kNN近傍点の `X_p` 位置から局所PCA（上位5成分）で
接平面基底 `T` を求め、

```
v_target^tangent = Tᵀ (T v_target)
```

で `v_target` を射影する。さらに、フェーズ2のKDEエネルギー場（本フェーズでは
逆変換の明快さのため`X_p`空間で再学習したもの）のスコアを弱い重み `β=0.3` で加算する
——design.md§3「エネルギー場の谷を人工的に深くする」という仮説の直接的実装である:

```
v_field = v_target^tangent + β・‖v_target^tangent‖・(∇_X_p log p(X_p))_hat
```

**4.2.4 raw特徴空間への逆変換**。scene残差化・標準化・PCAは全て線形写像であるため、`X_p`空間の
方向は解析的に2048次元のBlk-13 raw特徴空間の方向へ逆変換できる（PCA成分の行が正規直交である
ことを利用: `Δ X_std = v_X_p ・ components`）:

```
Δ X_raw = (v_field ・ components_prog_pca) ⊙ scale_ambient
```

この `Δ X_raw` を単位ベクトルに正規化し、`α` 倍してBlk-13のaction-token出力に
加算する（`steering_intervention.py`の`SteeringHook`と同じ注入点・書式。介入は5ステップの
デノイジングスケジュールのうち早期k=(0,1)、既存steering実験の標準スケジュールを踏襲）。

**4.2.5 実行手順（1 policy call毎）**: (i) このcallのBlk-13特徴（最終デノイジングステップ）を
捕捉し、状態推定器を更新して `D_t, X_p,t` を得る。(ii) `v_field(D_t)` を計算し、
次のcallで使うsteeringベクトルとしてフックにセットする（1 call分の遅延を伴うclosed-loop制御、
現在のcallに影響が出るのは次のcallから）。(iii) 次のcallの推論時、フックが早期k=(0,1)で
Blk-13の action-token 出力に `α ・ (Δ X_raw)_hat` を加算する。

**4.2.6 P6/P7の遵守**。先行検証で確立された不変原則を踏襲する: T1（`α=0`時、フック
あり/なしで出力完全一致）を実行前に必ず確認する。因果主張は定義した空間（D/`X_p`）の外
（実際のロールアウト行動・成功率）で検証する。

**4.2.7 条件設計**（全てPnPCounterToCab、`N=8` episode/条件、matched seed系列、`text_directions.pt`
から先行検証§10.4が既に計算済みの"neg_filler"埋め込み——"The weather today is sunny."——を
ダミープロンプトとして再利用）:

| 条件 | プロンプト | steering | 目的 |
|---|---|---|---|
| C0_real_prompt_no_steer | 実プロンプト | なし | 現状の性能の再確認（基準） |
| C1_dummy_no_steer | ダミー | なし | 言語なしでは何が起きるかの基準 |
| C2_dummy_dynamic_field | ダミー | 動的フィールド | **本検証の主対象** |
| C3_dummy_static_v_steer | ダミー | 静的（`v_steer`、§10と同一） | 動的介入が静的介入に優る/劣るかの比較 |
| C4_dummy_random_field | ダミー | 動的フィールド、方向ランダム化 | 方向特異性コントロール |
| C5_dummy_dynamic_field_frozen_obs | ダミー | 動的フィールド、観測をcall0に固定 | 感覚フィードバック従属性コントロール（§5） |

`α=40.0`（先行検証のBlk-13典型特徴norm≈196.2に対する比≈20.4%、§10.2でtaskを破壊した
`α=8`〜`16`の比85〜171%より小さいが、§10.1でtarget行動を誘発できなかった`α=4`の比
42.7%と同オーダー）を使用した。

### 4.3 結果

**T1 (α=0 no-op) 確認**: max|Δaction| = **0.00e+00**（フック挿入前後で完全一致、P7準拠）。

**フックの実効注入量**: C2（動的フィールド）の全episodeでhookの実効delta最大値は26.1〜27.0
（ambient比 13.3〜13.8%、典型特徴normの1割強——決して無視できない摂動量）。全条件・全episode
（`6 × 8=48`）を通じてNaN/Infアクションは0件だった。

| 条件 | success_rate (n=8) |
|---|---|
| C0_real_prompt_no_steer | **0.50** |
| C1_dummy_no_steer | 0.00 |
| C2_dummy_dynamic_field | 0.00 |
| C3_dummy_static_v_steer | 0.00 |
| C4_dummy_random_field | 0.00 |
| C5_dummy_dynamic_field_frozen_obs | 0.00 |

C0（実プロンプト・steeringなし）のsuccess_rate=0.50は、attractor_verification_report.md §10.1の
同一タスク・同一seed系列でのalpha0基準（success_rate=0.50）と完全に一致し、本検証の新規実装
（フック機構・環境セットアップ）が既存基盤と整合していることを確認する追加のサニティチェックとして
機能した。

**C1〜C5は全てsuccess_rate=0.00（8エピソード中0）だった**——ダミープロンプト下では、steeringの
有無・種類（動的フィールド／静的／ランダム方向／観測固定）によらず、8エピソード全てが最大ステップ
数（500）まで走り、一度もタスクを完遂しなかった。

### 4.4 解釈（都合の良い部分だけを取り上げない）

- **中心仮説「言語なしでもベクトル場介入によりタスク関連行動が自律的に誘発される」は、本検証で
  テストした範囲では明確に反証された**。動的フィールドsteering（C2）は静的steering（C3、
  attractor_verification_report.md §10と同一のv_steer）・ランダム方向のフィールド介入（C4）と
  success_rateにおいて全く区別できない（3条件とも0/8）。フックの実効注入量が典型特徴normの
  13%強という決して無視できない摂動量であったこと、T1が完全なno-opを示したこと（フック機構
  自体は正しく動作している）を踏まえると、この結果は実装の不備ではなく、**このパラメータ範囲
  （単一層Blk-13・早期k=(0,1)・α=40・タスクPnPCounterToCab）では動的フィールドsteeringが
  ターゲット行動を誘発する因果効力を持たない**という否定的知見として受け止めるべきである。
- **これは先行検証（attractor_verification_report.md §10.1-10.3）の「特定スキルの活性化は
  反証されたが、必要条件的な因果力は持つ（タスク破壊は起こせる）」という、より精緻な因果構造の
  延長線上にある**。ただし本検証ではタスク破壊すら観測されなかった——なぜならC1（steeringなしの
  ダミープロンプト単体）が既にsuccess_rate=0.00まで崩壊しており、「これ以上破壊しようがない」
  床効果（floor effect）にすでに達していたためである。したがって本検証は「動的フィールド
  steeringがタスク破壊を引き起こすか」を検定する検出力を実質的に持たない——C1の時点で床に
  張り付いているため、C2〜C5がC1から統計的に区別できないことは、動的フィールドsteeringに
  効果がないことの証拠にも、効果があることの証拠にもならない、という限定的な解釈にとどめる
  べきである。
- **「言語プロンプトが伝える情報は、この設定では視覚情報だけでは代替できない」ことが、
  C1（success_rate=0.00）から明確に確認された**——PnPCounterToCabはキッチンシーン内の複数の
  操作可能物体・複数の起こりうる操作（pick, place, open, close等）を含みうるタスクであり、
  「どの物体をどうする」という情報の大部分は言語プロンプトが担っている可能性が高い。設計書の
  「ハサミを見たら切る」という比喩は、視覚的に一意な単一のアフォーダンスを持つ対象を想定した
  ものだが、本検証の実タスクはそのような単純化された条件を満たしていない可能性がある——これは
  本検証の否定的結果を解釈する上で重要な文脈である（§4.6・§9参照）。
- フェーズ4（§5）でより細かい粒度の指標（軌跡形状・多様体逸脱度・感覚フィードバック従属性）を
  見ることで、「行動としては成功しなかったが、何らかの部分的・準連続的な効果はあったか」を
  追加で検討する。

### 4.5 結論

**反証**。テストした範囲（単一タスクPnPCounterToCab、単一層Blk-13、早期k=(0,1)、`α=40`）
では、動的フィールドsteeringは静的steering・ランダム方向介入と区別できず、いずれもダミー
プロンプト下でのタスク完遂を一切誘発しなかった。ただし、ダミープロンプト単体（C1）が既に
success_rate=0で床効果に達していたため、「動的介入が静的介入より優れている」「劣っている」の
いずれの主張も、success_rateという指標だけからは支持できない——より細かい指標が必要である
（§5）。

### 4.6 注意点・限界

1. 状態推定器（causal state estimator）はscene残差化をエピソード内累積平均で近似しており、
   エピソード序盤ほど残差化の精度が低い（call 0は自明に0）。
2. steeringベクトルの適用には1 call分の遅延がある（closed-loop制御の構造上の制約）。
3. `α` の値は予備的なスモークテストで妥当な摂動量（典型ambient normの十数%程度）になる
   よう選定したものであり、網羅的なdose-responseスイープは実施していない（§9参照）。
4. 単一タスク（PnPCounterToCab）・単一層（Blk-13）・単一スケジュール（早期k=(0,1)）でのみ
   検証した。
5. `N=8`/条件は、成功率のような二値指標の検出力としては小さい（先行検証のsteering実験と
   同規模、§10.1の限界と同じ）。

### 4.7 今後の検証案

- `α` の網羅的なdose-responseスイープ。
- 他タスク・他層・他スケジュールへの一般化。
- `β`（エネルギー勾配の重み）を0にした場合とのアブレーション比較。

## 5. フェーズ4：評価指標

### 5.0 要旨

フェーズ3の全ロールアウトログから3指標を計算した。**動的因果効力（教師軌跡とのDTW/Fréchet
距離）と多様体逸脱度では、C2（動的フィールド）はC1（steeringなし）・C3（静的）・C4（ランダム）
のいずれとも統計的に区別できなかった**（Mann-Whitney、いずれも `p>0.16`、`N=8`）——§4の
success_rateレベルの否定的結果は、より連続的な軌跡形状の指標でも覆らなかった。一方
**「感覚フィードバックへの従属性」指標では、非常に明確な肯定的結果が得られた**: 同一の動的
フィールドsteering設定下で、観測を通常通り更新した条件（C2）は観測をcall 0に固定した条件（C5）
よりエンドエフェクタ経路長が平均**4.20倍**長く（Mann-Whitney `p=7.8×10^-5`）、行動の
時間的変化（action標準偏差）もC5で顕著に低い（0.128 vs 0.011）。**タスクの完遂には至らなかった
ものの、動的フィールドsteering下の行動は明らかに生きた感覚入力に従属して変化しており、固定的な
既定動作の再生には陥っていない**——これは設計書の現象学的枠組みが要求する「感覚運動随伴性」が
（目的の達成とは独立に）保たれていたことを支持する、本検証で最も明確な肯定的知見である。

### 5.1 目的

設計書フェーズ4は、フェーズ3の動的介入の効果を(1) 動的因果効力、(2) 多様体逸脱度、
(3) 感覚・環境フィードバックへの従属性、の3指標で定量評価することを要求する。本節はこれらを
フェーズ3の全ロールアウトログ（`dynamic_vector_field_steering_PnPCounterToCab.json`）から
計算する。

### 5.2 手法

**5.2.1 動的因果効力 (Dynamic Causal Efficacy)**。各ロールアウトのエンドエフェクタ軌跡
（env-step粒度で記録済み）が、教師軌跡（`collect_v2/`の成功エピソードのエンドエフェクタ位置系列、
call粒度、`N ≤ 15`）とどの程度形状的に一致するかを、DTW距離と離散Fréchet距離
（Eiter & Mannila 1994の標準的DP実装、いずれも追加依存なしの自前実装）で測定する。粒度の違いに
よる不公平を避けるため、比較前に両軌跡を弧長パラメータ化で同一個数（20点）のウェイポイントへ
リサンプルする。各ロールアウトについて、`N`個の教師軌跡のうち最小距離（最も近い教師との一致度）
と平均距離の両方を報告する。

**5.2.2 多様体逸脱度 (Manifold Deviation)**。フェーズ1が保存した成功エピソードのみの進行度
ビン参照分布（§2の`fit_bin_reference`/`deviation_from_reference`、循環回避のため成功エピソードの
みで学習）を、フェーズ3がオンラインで既に計算・保存済みの各ロールアウトの`X_p`軌跡
（`xp_traj`）に適用する。ロールアウトは全て新規収集データであり参照分布の学習に一切使われて
いないため、循環性の問題は生じない。

**5.2.3 感覚・環境フィードバックへの従属性**。design.mdは「観測を変化させた際、出力アクションが
Reactiveな一定出力にならず、不変量を維持したまま柔軟に調整されるか」を問う。C2（通常observation）
とC5（observationをcall0の1枚に固定、環境自体は実際に進行）を同一のsteering設定下で比較する
直接統制条件を用いる。行動系列の複雑さの指標として、エンドエフェクタ経路長
`Σ_t ‖eef_t+1 - eef_t‖`（episode単位）を用い、C2がC5を有意に上回れば
（Mann-Whitney、片側）、steering下の行動が観測に従属して柔軟に変化していること（単なる固定的な
既定動作の再生ではないこと）の証拠とする。

### 5.3 結果

**動的因果効力・多様体逸脱度**（教師軌跡`N=15`、`collect_v2/`の成功エピソード）:

| 条件 | success_rate | 教師との最小DTW距離 | 教師との最小Fréchet距離 | 多様体逸脱度(mean) | 経路長(mean) | action標準偏差(mean) |
|---|---|---|---|---|---|---|
| C0_real_prompt_no_steer | 0.50 | **0.072** | **0.283** | 4.821 | 2.292 | 0.164 |
| C1_dummy_no_steer | 0.00 | 0.212 | 0.566 | 4.961 | 2.509 | 0.135 |
| C2_dummy_dynamic_field | 0.00 | 0.202 | 0.564 | 4.886 | 2.493 | 0.128 |
| C3_dummy_static_v_steer | 0.00 | 0.231 | 0.596 | 4.974 | 2.542 | 0.140 |
| C4_dummy_random_field | 0.00 | 0.229 | 0.635 | 4.935 | 2.540 | 0.142 |
| C5_dummy_dynamic_field_frozen_obs | 0.00 | 0.151 | 0.483 | **3.406** | **0.594** | **0.011** |

C2 vs 他ダミー条件のMann-Whitney検定（片側、C2が下回るか）: DTW — vs C1: `p=0.361`、vs C3:
`p=0.164`、vs C4: `p=0.191`。多様体逸脱度 — vs C1: `p=0.253`、vs C3: `p=0.287`、vs C4:
`p=0.480`。**いずれも有意水準に届かない**。

**感覚フィードバックへの従属性**（C2 vs C5、同一のsteering設定）: 経路長比（C2/C5）=
**4.197**、Mann-Whitney（片側、C2がC5を上回るか）`p=7.77×10^-5`。C2の8episode全ての
経路長（2.21〜2.69）がC5の8episode全ての経路長（0.27〜1.59）を上回り、完全に分離している。

### 5.4 解釈（都合の良い部分だけを取り上げない）

- **動的因果効力・多様体逸脱度では、動的フィールドsteering（C2）が他のダミー条件と統計的に
  区別できなかった**——DTW距離はC2（0.202）が数値上はC1（0.212）よりわずかに小さい（教師に
  近い）が、C3（0.231）・C4（0.229）とほぼ同程度であり、統計的検定はいずれも非有意
  （`p>0.16`）。§4の否定的結果（success_rate）は、より連続的で「部分的な成功」も拾えるはずの
  軌跡形状指標でも覆らなかった——動的フィールドsteeringには、タスク成功に至らない範囲での
  「教師デモに似た動きへの部分的な引き込み」すら検出できなかった、というのが正直な結論である。
- **C5（観測固定）のDTW/Fréchet距離が他の全条件より小さい（教師に近い）という結果は、字面通りに
  「教師デモに最も似た動きをした」と解釈すべきではない**——C5の経路長は他条件の1/4以下
  （0.594 vs 2.29〜2.54）であり、ほとんど動いていない。ほぼ静止した短い軌跡が、弧長リサンプル後の
  DTW/Fréchet距離で小さい値を示すのは、軌跡形状が教師と一致しているからではなく、単に「動かない
  こと」が（動きすぎて教師から大きく逸脱するよりは）平均的に近い距離になりやすいという、指標の
  長さへの感度に起因するアーチファクトである可能性が高い。**この点は指標設計上の限界として
  明記する**（§5.6）。
- **一方、「感覚フィードバックへの従属性」指標は本フェーズで最も明確で頑健な結果を示した**——
  同一のsteering設定（同じ`α`・同じフィールド関数）にもかかわらず、観測を生きたまま
  更新するか（C2）call 0に固定するか（C5）だけで、経路長に4.2倍・完全分離という劇的な差が生じた
  （`p=7.8×10^-5`）。action標準偏差もC5で1桁小さい（0.011 vs 0.128）——観測が変化
  しない場合、行動はほぼ一定値に収束し、design.mdが警戒する「Reactiveな一定出力」に近い状態に
  陥ることが確認された。**これはC2がその状態には陥っていない、すなわち動的フィールドsteering
  下の行動生成は（タスクの完遂には至らずとも）依然として生きた感覚入力に応答的に結合されている
  ことの強い証拠である**。「行為が感覚運動ループとして機能しているか」という設計書の根底にある
  問い（§4現象学的背景）に対して、本検証全体で唯一、明確に肯定的な答えを与える結果である。

### 5.5 結論

動的因果効力・多様体逸脱度では動的フィールドsteeringに他条件との有意差はなく（`N=8`の検出力の
範囲では）、§4のsuccess_rateレベルの反証を補強する形となった。一方、感覚フィードバックへの
従属性は明確かつ頑健に支持され（`p=7.8×10^-5`、完全分離）、「動的フィールドsteering下の
行動生成はタスクを完遂できないが、感覚運動ループとしては機能し続けている」という、本検証全体を
通じて最も精緻な結論が得られた。

### 5.6 注意点・限界

1. 教師軌跡はcall粒度、ロールアウトログはenv-step粒度であり、リサンプルによる比較は近似である。
2. DTW/離散Fréchetは3次元エンドエフェクタ位置のみを対象とし、グリッパー開閉やオリエンテーション
   は含まない。
3. 感覚フィードバック従属性の統制（C5）は「観測をcall0固定」という1種類の操作のみであり、
   より段階的な観測摂動（部分的なノイズ付加等）は未実施。

### 5.7 今後の検証案

- グリッパー開閉・オリエンテーションを含めた行動全体でのDTW/Fréchet再計算。
- 段階的な観測摂動（ノイズレベルを変えた統制）での感覚フィードバック従属性の再検定。

## 6. 統合結論

本検証は、設計書が要求する「感覚と運動の結合動態を一次的対象として扱う」というエナクティヴィズム
的アプローチを、先行2検証が確立した基盤の上に実装し、4フェーズを通じて完全に実行した。

**構築（フェーズ1・2）は成功した**。感覚（潜在表現の進行多様体）と運動（エンドエフェクタ・
グリッパーの物理的効果）を結合した遅延座標埋め込み空間Dは、低次元性・成功/失敗の統計的分離
可能性という、先行検証が確立した進行多様体の基本的性質を壊さずに構築できた。さらに、この結合
表現の上で§5.7のDMD力学解析を再評価したところ、PnPCounterToCabにおいて元の潜在表現単体では
見えなかった「成功=自己安定化・失敗=不安定化」という力学的シグナルが統計的に有意な形で現れた
（`X_p`空間: `p=0.38`〜`0.59`、非有意 → D空間: `p=0.023`）——これは「観測と行動を分離すると
本来の構造が見えなくなる」という設計書の中心的仮説を支持する、具体的かつ新規性のある肯定的知見
である。D空間上のエネルギー場も、「成功=谷、失敗=リッジ」という大局的パターンを明確に支持した
（`p<10^-6`、ただし窓単位の細かい粒度での力学的不安定性との直接対応は支持されなかった）。

**しかし、本検証の中心的な因果仮説——「言語プロンプトなしでも、ベクトル場への動的介入により
モデルが自律的にタスク関連の感覚運動ループへ引き込まれる」——は、テストした範囲では反証された**。
ダミープロンプト下では、動的フィールドsteering・静的steering・ランダム方向介入のいずれも
success_rateを一切改善せず（全て0/8）、より連続的な軌跡形状指標（教師デモとのDTW/Fréchet距離、
多様体逸脱度）でも動的介入が他条件から統計的に区別できなかった。これは先行検証（§10.1-10.3）が
静的steeringについて確立した「特定スキルの活性化は不可能」という反証を、動的なフロー介入という
質的に異なる介入方式に対しても拡張する結果である。

**一方、本検証で唯一かつ最も頑健な肯定的知見は、感覚フィードバックへの従属性である**。動的
フィールドsteering下の行動は、タスクを完遂できないにもかかわらず、観測が生きたまま更新される
限り豊かに変化し続け（経路長・行動の分散ともに大）、観測を固定すると劇的に（4.2倍、
`p=7.8×10^-5`）縮退した。つまり、**この動的介入は「特定の目標指向的スキル」を誘発する
因果効力は持たないが、生成される行動それ自体は最後まで感覚運動ループとして機能し続けていた**
——設計書が拠って立つ現象学的主張（行為は感覚運動の結合動態の中で立ち現れる、observationからの
reactiveな出力ではない）は、目的達成の成否とは独立に、この一点においては支持された。

総括すると、本検証は「感覚運動を結合した表現空間は構築可能であり、元の表現では見えなかった
力学的構造を（少なくとも1タスクで）顕在化させうるが、その表現空間上のベクトル場を用いた動的
介入で、言語なしに特定のタスク行動を自律的に誘発することはできなかった」という、部分的に肯定的
・部分的に否定的な結果を与えた。この否定的な部分について、最も可能性の高い説明は、PnPCounterToCab
というタスクが「ハサミを見たら切る」のような単一で一意なアフォーダンスを持つ対象ではなく、
複数の操作可能物体・複数の起こりうる操作を含む複雑なシーンであり、そこでの「どの物体をどう
扱うか」という選択情報の大部分を言語プロンプトが担っていた、というものである（§9参照）。

## 7. 実装の詳細：発見・修正したバグ

検証中に発見し、結果に影響する前に修正した実装上の不具合を全て記録する（実装の透明性のため、
attractor_verification_report.md §14の慣行に倣う）。

1. **結合ベクトル`c_t`のスケール未統一バグ**（`dynamics_embedding_test.py`）: フェーズ1の
   結合ベクトル `c_t = [X_p,t, V_t, Δeef_t, Δgrip_t]` の4ブロックは
   物理的に全く異なるスケールを持つ（`X_p,V`はPCAスコア単位でstd〜O(5〜20)、`Δ`eefは
   メートル単位でstd〜O(0.01)）。これを標準化せずに遅延埋め込みPCAへ入力すると、PCAの分散は
   `X_p,V`ブロックにほぼ完全に支配され、D空間が数値的に`X_p`の単なる回転に退化し、eef/gripper
   の行動効果情報が実質的に失われる——「感覚運動を結合した表現」という本検証の目的そのものを
   骨抜きにする不具合だった。`c_t` を標準化してからPCAへ入力するよう修正した。
2. **フローの非因果的リーク（forward differenceのオフライン専用性の見落とし）**
   （`dynamics_embedding_test.py`）: 当初、結合ベクトルの `V_t` を forward difference
   `X_p,t+1-X_p,t` で定義していた。これはオフライン（既に完結したロールアウトの事後解析）
   では問題ないが、この同じ関数をフェーズ3のオンラインsteeringフックが再利用する設計だった
   ため、そのままでは「ロールアウト実行中のcall `t` の時点で、まだ起きていないcall `t+1` の
   結果を使う」という原理的に不可能な非因果的リークを埋め込むことになっていた。修正前・修正後
   でD空間上のDMD解析結果（PnPCounterToCabの§5.7再評価）が定量的に変化したことを確認しており
   （修正前: `p=6.85×10^-7` 、修正後: `p=0.023`）、単なる理論上の懸念ではなく実際に
   結果に影響する不具合だった。backward difference（`t`対`t-1`）に修正し、オフライン・
   オンライン双方で同一の（因果的な）定義を使うようにした。
3. **Mann-Whitney検定の天井効果を「バグ」と誤認しかけた件**（`dynamics_embedding_test.py`）:
   D空間と`X_p`空間の逸脱量検定で、実際の逸脱量（平均2.44 vs 2.86等）が異なるにもかかわらず
   p値が小数点以下15桁まで完全一致するという現象に遭遇し、当初は計算バグを疑った。調査の結果、
   両空間とも成功/失敗の逸脱量分布が完全に非重複（min(fail) > max(succ)）であり、この場合
   Mann-Whitney U統計量は群サイズのみで決まる最大値に張り付くため、p値が値の大小によらず
   一致することが正しい振る舞いだと判明した（バグではない）。この天井効果下でも空間同士を
   比較できるよう、正規化逸脱マージンを追加の効果量として導入した。
4. **`DynamicFieldHook.last_delta_max`の診断値が常に0を報告するバグ**
   （`dynamic_vector_field_steering.py`、`steering_intervention.py`のSteeringHookから
   継承したパターン）: フックの`_hook()`内で、k_range条件を満たさない**全ての**呼び出しで
   `self.last_delta_max = 0.0`と無条件にリセットしていた。1回のget_action()呼び出しは
   デノイジングstep順（0→4）にフックを複数回発火させ、steeringのk_rangeは早期（例: (0,1)）
   であることが多いため、必ず**最後**に発火するstep=4（k_range外）が無条件リセットで
   それより前のstep=0/1で記録された正しい非ゼロ値を毎回上書きしてしまい、実際には介入が正しく
   適用されているにもかかわらず診断値`last_delta_max`が常に0を報告していた。この不具合により
   フェーズ3の最初のスモークテストで「介入が全く効いていない」と誤って結論しかけた——実際には
   介入自体（`output[...] += delta`の行）は正しく実行されており、影響を受けていたのは診断用の
   最大値トラッキングのみだった。リセットをcall単位（`reset_step()`内）に移し、`_hook()`内では
   `max()`で更新するよう修正した。**この同じパターンは`steering_intervention.py`の
   `SteeringHook`にも存在する**——ただし当該レポート（attractor_verification_report.md）の
   実質的な結論は`frac_closed_at_checkpoint`・`success_rate`・独立プローブという実測の行動
   指標に基づいており、`max_hook_delta_observed`という診断フィールド自体が文中の主張の根拠に
   使われている箇所は確認できなかったため、この不具合が当該レポートの結論に影響したとは考え
   にくい。修正は本検証の新規コードにのみ適用し、`steering_intervention.py`本体は変更していない
   （既存結果を壊さないため）。
5. **RoboCasaテクスチャアセットの壊れたシンボリックリンク**（環境設定、コードのバグではない）:
   `robocasa-cosmos-policy/robocasa/models/assets/textures`・`generative_textures`が、
   もはや存在しないパス（`/mnt/data/bilgehan.sakai/tmp_home/Flow_Policy/...`、別プロジェクトの
   旧アセット配置）を指すシンボリックリンクのままになっており、環境生成が
   `white_tiles.png`のファイル未検出で即座にクラッシュしていた。`textures`は
   `/mnt/data/bilgehan.sakai/cosmos-policy/cache/robocasa_assets/textures_extracted/textures`
   （本プロジェクト自身が保持するローカル展開済みアセット）に張り替えて解消した
   （`generative_textures`は本検証で使用するタスクでは必要にならず未対応のまま、§9参照）。

## 9. 今後の課題

個別の検証に紐づく今後の検証案は各節末尾に記載した（§2-5）。以下は複数のフェーズにまたがる、
または検証全体の設計に関わる横断的な課題である。

1. **他タスクへの一般化** — フェーズ3・4は全てPnPCounterToCabのみで検証した（先行検証の
   steering因果テストと同じスコープ制約）。特に§6で述べた「複数の操作可能物体を含む複雑な
   シーンでは視覚だけでは選択情報が足りない」という仮説を検定するには、CloseDrawerや
   CoffeePressButtonのような、シーン内の操作対象がより一意なタスクでの追試が望ましい——設計書の
   「ハサミを見たら切る」という比喩に近い条件を作れる可能性がある。
2. **非線形自己符号化器によるD空間構築** — 本検証の線形PCA版と比較する。
3. **`X_hat_0`（生成行動チャンク）の捕捉** — 現状はeef_pos/gripper_qposという環境物理量の
   差分で代替しているが、モデルが実際に生成した行動そのものを結合ベクトルに含めることで、
   より設計書の定式化に忠実な検証が可能になる。
4. **視覚特徴の勾配（attention mapの時間微分）の追加** — 未捕捉のまま。
5. **`generative_textures`シンボリックリンクの修復** — 本検証で使用したタスクでは不要だったが、
   generative texture variantを使う他タスク・他検証では引き続きブロッカーになりうる。
6. **§フェーズ3のα網羅的スイープ・他層/他スケジュールへの拡張** — 先行検証のsteering拡張検証
   （§10.2-10.3）と同等の頑健性確認を、動的フィールドsteeringに対しても行う。
