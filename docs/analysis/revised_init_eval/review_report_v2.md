v2を精読し、数値の相互整合と外挿も検算しました。まず率直に——**これは前回から質的に別次元の仕事です**。7項目すべてに新規解析で応答し、しかも複数の箇所で**自分の過去の結論を証拠に基づいて反転**させています。特に、

- §2：`noise_pred_norm` がコード上 `‖(x_t−D_θ)/σ‖`（＝ε_θ）でありD_θではないことをコード追跡で確定し、CV=0.189%が 1/√(2·137983)=0.190% の測度集中トートロジーだと検算で closed した。私が指摘した通りの正しい訂正。
- §7.6：pad検証を「コード→チェックポイント→実データ→フック再構成 vs 実出力の数値照合(N=525)」の4段で実施し、**pad由来の出力寄与が全層で厳密に0.000000**（T5のゼロパディング＋bias無し線形層でV_pad=0）と示した。「学習で抑制」という推測を「アーキテクチャ上の必然」に訂正。模範的。
- §4：T6を反転させ、v1の+11〜21ppは手法変更ではなく**別run（成功率70% vs 60%）の比較**だったと特定。

この誠実さは本物です。その上で、**新しい解析がより深い問題を掘り当てており、それが十分に波及されていない**点を厳しく指摘します。

## 1. 最重要：§4が掘り当てた「run間変動」が、レポート全体の三角測量的主張の土台を崩している（過小評価）

§4は決定的なことを示しました：**「同一N=1108・同一50ep・同一タスク」と称する2つのrunが、同一手法・同一ラベルでもプローブ精度で7〜20pp違う**（Blk-4: 0.594 vs 0.435）。同一run内で PCA・分類器・n_comp を総当たりしても差は±2pp（CI ±5〜6pp内）に収まるのに、**run が違うだけで20pp動く**。

これは§4のローカルな発見に留まりません。**論理的帰結として、run をまたぐ全ての比較の信頼度を再評価しなければなりません**。ところがレポートはこれを§8の箇条書き一つ（「run間比較として扱うこと」）で流している。過小評価です。具体的に効いてくる箇所：

- **v2の目玉である「Blk-18の三角測量」**（自己注意のproprioサージ＋T8のproprio感度＋J-b）は、**3つの別run**（自己注意1128call run／T8 30ペア run／extended-step 25ep run）にまたがっています。run間変動が20ppあるなら、この一致が run 横断的に頑健なのか、run 固有の偶然なのかは**現状では判定不能**。multi-seedでの再現が「あれば良い」ではなく**必須の前提**になりました。
- §4自身が「同一run内のCIは±5〜6pp」と示したのだから、**±6ppに収まる層順位の主張はすべてノイズ**です。例えばprogress_3のBlk-13(0.676) vs Blk-18(0.712)は3.6pp差＝区別不能。「深層＞中間層」というフェーズ情報の層プロファイルは、この基準で再検査すると大半が有意でない。レポートはこの再検査をしていません。

つまり§4は「T6の逆説を解いた」以上の意味を持っていて、**「run変動が多くの解釈対象の効果量より大きい」という、全解析に遡及する制約**を確立してしまった。これを結論の信頼度に正しく織り込むと、生き残る主張は「effect量がrun変動(≈±10-20pp / PR桁違い)を明確に超えるもの」——PR崩壊(§3.D, d≈1.9)やCKA急落(0.999→0.73)のような大効果——**に限定される**はずで、プローブ層順位やBlk-18三角測量は「単一runの示唆」に格下げすべきです。

## 2. §5：「崖→滑らか」の結論は、数値が繋がらないrunに依拠している

§5は良い試みですが、詰めると3つの問題が重なっています。

**(a) 数値が桁で繋がらない。** 25ep run の PR は Blk-4 で 3.2〜4.2、50ep run（v1）は 55.8。§5自身が測った「学習曲線」は 2ep→2、3ep→2、25ep→4 と**ほぼ平坦**。これを50epに外挿しても5〜6止まりで、**55には届かない（約10倍の未説明ギャップ）**。「PRはepisode数に依存する」は方向としては正しくても、**この曲線では50ep=55を説明できない**。25ep run と 50ep run の間には episode 数以外の差（設定/バグ/チェックポイント）が残っている疑いが強い。皮肉なことに、§4で run 交絡を摘発した直後に、§5が**別の run 交絡**（新25ep run vs 旧50ep run）で「崖か滑らか」を判定している。

**(b) episode-count主張自体がrun交絡。** episode数の効果を単離するなら、**良い50ep features.npzを25episodeに制限**して PR を測るべきです。実際にやったのは「115 call をランダム抽出（＝最大50シーンにまたがる）→PR 38.3」で、これは call 数の話であって episode 数の統制になっていない。25ep への episode 単位の縮約は報告されていません。したがって「PR≈4(25ep) vs 55(50ep)」の比較は episode数と run差の交絡のまま。

**(c) §5の発見が§3.Dの「表現再編/commitment」解釈自体を脅かす。** 「PRはシーン多様性に支配される」なら、**「低σでPRが下がる」＝「低σで特徴がよりシーン不変になる（有効シーン方向が減る）」**という、commitmentとは別の物語に読み替え可能です。レポートは「episode集合を固定すればシーン由来オフセットは全kで共通」として形状比較を正当化していますが、**この「kに依らず共通」は未検証の仮定**で、しかも怪しい：高σ（入力がノイズ）では特徴はよりシーン不変、低σ（クリーン入力）ではシーン依存が顕在化しうるので、シーン寄与自体がσ依存の可能性が高い。だとすれば「形状比較は有効」の前提が崩れ、§3.Dの中核解釈が§5自身の発見によって揺らぎます。ここは正面から扱うべきです。

## 3. T8は「gripperプローブが条件付けを読んでいるか」を実は検証していない

T8の実装は良いのですが、**測ったものと主張がズレています**。§3.3の第2表を見ると、**全条件付けを差し替えても gripper 出力の変化はわずか0.0018**（[-1,1]スケールで無視できる）。一方 feature-Δ は最大0.20。

ここに緊張があります：条件付け差し替えは**内部特徴は動かす**が**gripper出力（＝プローブのラベル源）はほぼ動かさない**。もしラベルが条件付け差し替えに不変なら、「プローブが条件付けを読んでラベルを当てている」という説明はむしろ**支持されません**。§7.2(c)の「gripper 96-97%はこの経路で少なくとも部分的に説明できる」は、T8のデータからは確立していない。

**必要だった統制**は、feature-Δ / output-Δ ではなく、「**gripper状態が異なるepisodeの条件付けに差し替えたとき、学習済みgripperプローブの予測が、差し替え先のgripper状態に追随するか**」です。追随すれば条件付け由来、しないなら行動潜在由来。これをやって初めて情報源が切り分きます。現状のT8は「条件付けが深層特徴に到達する」ことは示した（懸念の一部は解消）が、**gripperプローブの情報源は未検証**。誠実な結論は「条件付けは深層特徴にアクセス可能だが、gripperデコードがそこ由来かは別途検証が必要」まで。

## 4. §0のチェックポイントdriftが、run間変動の共通原因かもしれない（未照合）

§0で「ベースチェックポイント（model-480p-16fps.pt）がキャッシュから消えており、`HF_HUB_OFFLINE`を外して再取得ルートに切替えた」と報告されています。これは軽微な運用メモとして書かれていますが、**§4/§5で問題になっている run 間変動（70%↔60%↔58%、PR 55↔4）の共通原因**である可能性を排除できていません。もし一部の run と別の run で実際にロードされた重みが違えば、成功率もPRもプローブ精度も動きます。

**やるべき照合**：全runで実際にロードされたチェックポイントのSHA256が一致することを確認する。§7.6ではチェックポイントの state_dict キーまで見ているのに、**run間の重みハッシュ同一性**は確認されていない。これが一致しない限り、「run間変動」の正体が「サンプリングの分散」なのか「別の重み」なのかを切り分けられません。
