## 1. 共通基盤：Run管理・Provenance・成功率ゲート

### 1.1 単一の Run Manifest を真実の源とする

すべての解析は `run_manifest.json` を参照し、どのrunのどのテンソルを使ったかを記録する。

```json
{
  "run_id": "2026xxxx_seedNNN_hookMODE",
  "task": "PnPCounterToCab",
  "n_episodes": 50,
  "seed": 195,
  "hook_mode": "observe_only | passthrough_recompute | none",
  "success_rate": 0.60,
  "n_policy_calls": 1108,
  "sigma_schedule": [80.0, 42.29, 20.97, 9.62, 4.0],
  "git_commit": "…",
  "device": "cuda:0 (CUDA_VISIBLE_DEVICES=1)",
  "capture_fingerprints": { "features.npz": "sha256:…", "…": "…" }
}
```

- **どの解析も、使用したrun_idを結果JSONの先頭に必ず記録**する。
- 「results_01/02/03/04が整合」と主張する場合は、**同一run_idを共有していることを明記**する。異なるrunなら「run間比較」と明示し、成功率・call数の差を注記する。

### 1.2 成功率ゲート（P2 の実装）

アテンション系解析を回す前に、**instrumentモデルの成功率がベースライン（フックなし）と統計的に一致すること**を確認する。

| 手順 | 内容 | 合否基準 |
|------|------|----------|
| G1 | フックなしで50ep実行し、baseline成功率 `p0` を取得（複数シードで CI 付き） | — |
| G2 | フックあり（観測モード）で同一シードで再実行し `p1` を取得 | — |
| G3 | `p0` と `p1` の差を2群比率検定（Fisher/Barnard）で検定 | **有意差なし（p>0.05）かつ \|p0−p1\|<0.05 なら合格** |

**results_02/04 のように p1=0% となった場合は不合格**。その run のアテンション結果は一切採用しない。原因が切り分くまで解析を停止する（§2）。

## 2. 計測インフラの健全性検証（新規・最優先）

### 2.1 フックが出力を変えていないことの証明

FlashAttention の重み再構成が問題の中心。**「観測専用」と「フォワード差し替え」を厳密に分離**する。

- **観測専用モード（推奨）**: FlashAttention は本来経路のまま実行し、`q,k` を別バッファにコピーするだけ。ロジット・出力テンソルは一切変更しない。
- **検証テスト T1（出力不変性）**: 同一入力・同一シードで「フックあり／なし」のポリシー出力（x̂₀ の全T位置）を突き合わせ、`max|Δ| < 1e-4`（bf16の丸め相当）を確認。**超過したらフックが計算を汚染している** → 修正必須。
- **検証テスト T2（重み一貫性）**: 手計算 `softmax(QKᵀ/√d)` を、小規模ケース（padなし・短系列）で `torch.nn.functional.scaled_dot_product_attention` の内部重みと突き合わせ、`√d` スケール・因果/padマスク・数値精度（fp32で計算）が一致することを確認。

### 2.2 padマスク・正規化の検証（P8）

- 実トークン `n_real=15`、全長 `Sk=512`。**softmax前にpad位置へ −inf マスク**を適用してから重みを計算する。
- **検証テスト T3**: マスク後の各クエリ行の重み和が 1.0（±1e-5）であること、pad位置の重みが厳密に0であることをassert。**Top-kにpadが現れたら即fail**（results_02 のpos=218混入を再発防止）。

### 2.3 「独立解析の同一値」検出（P10 → results_02/04 の7桁一致バグ対策）

- 各解析が出力する数値配列に **内容ハッシュ**を付す。
- **回帰テスト T4**: 「クロスアテンション不変性テーブル」と「自己注意不変性テーブル」のように**別テンソル由来であるべき2配列のハッシュが一致したら CI を fail** させる。異なる次元（512 vs 11）・異なるQ/K由来の値が7桁一致するのは実装バグの確定的サイン。

## 3. 各解析の再設計

各節は **仮説 / 反証条件 / 計測対象 / 手法の修正点 / ヌル・ベースライン / 統計 / 成果物 / 合否ゲート** の順。

### 3.A デノイジング変化量（Confidence-to-Commitment）

- **仮説 H_A**: 各ステップの予測変化 `‖Δx̂₀(k)‖` は、σスケジュールから期待される以上に終盤へ単調集中する。
- **反証条件**: 線形ガウス・デノイザ（下記ヌル）が同じσスケジュールで生成する `‖Δx̂₀‖` プロファイルと**区別できなければ H_A は棄却**。
- **手法の修正点**:
  - **per-step 正規化**を併記する。生の `‖Δx̂₀(k)‖` に加え、(i) `‖Δx̂₀(k)‖ / ‖x̂₀(k)‖`（相対）、(ii) `‖Δx̂₀(k)‖ / |Δlog σ_k|`（スケジュール規格化）、(iii) `‖Δx̂₀(k)‖ / |Δσ_k|` を出す。単調増加が3系列すべてで残るかを見る。
  - 層別変化は**絶対L2を主指標にしない**。`‖Δfeat‖/‖feat‖` と `1−cos(feat(k),feat(k−1))` を主指標に（P6）。
- **ヌル・ベースライン B_A**: 同一σスケジュールで、既知の解析解を持つ線形ガウス過程（例：単純なTweedie/最適線形デノイザ）の `‖Δx̂₀‖` を計算。実測がこれと有意に異なる形状かを検定。
- **統計**: 1108callを episode 単位でブートストラップ（クラスタブートストラップ）し、各遷移の平均に95%CI。「k0→1 < k3→4」を**対応のある符号検定**で episode レベルに検定。
- **成果物**: `denoise_delta_{abs,rel,schednorm}.png`, `denoise_delta_vs_null.png`, `denoise_delta_stats.json`(CI・p値込み)。
- **合否ゲート**: 相対指標でも単調性が有意 かつ ヌルと有意差ありのときのみ「Confidence-to-Commitment確認」と記述可。

### 3.B 周波数解析（Spectral / Coarse-to-Fine）

- **仮説 H_B**: デノイジングの精緻化は低周波→高周波の順に進む。
- **手法の修正点（P7、最重要）**: 状態 x̂₀ のスペクトルではなく、**ステップ変化 Δx̂₀(k)=x̂₀(k)−x̂₀(k−1) のスペクトル**を解析対象にする。
  - アクション: 1D FFT を Δ に適用し、各遷移 k で**変化パワーの周波数重心**（spectral centroid）と低/高帯パワー比を算出。coarse-to-fine なら centroid が k とともに上昇するはず。
  - 画像ラテント: 2D FFT を Δ の 14×14 マップに適用し、**半径方向の変化パワー分布**の重心が k とともに外側（高空間周波数）へ動くかを見る。
  - 位相解析は Δ ではなく x̂₀ 対で妥当（タイミング不変の主張用）。維持。
- **ヌル B_B**: Δ が全帯域一様（白色）変化である帰無を作り、実測centroidの k 依存が有意かを permutation で検定。
- **統計**: centroid(k) の単調性を episode ブートストラップ CI 付きで検定。
- **成果物**: `delta_spectrum_centroid.png`(k依存), `delta_radial_power_by_k.png`。
- **合否ゲート**: 「coarse-to-fine 不成立」と書くには、centroid が k と無相関であることを**検出力込み**で示す（サンプル不足による無検出と区別）。

### 3.C スコア／preconditioning（std=0.701 問題の是正）

- **問題の核**: 旧「スコアノルム」は測度集中により √d に張り付き、σにも入力にも依存しない**無情報量**だった。
- **仮説 H_C**: EDM preconditioning は、σによらず**ネットワーク生出力 F_θ の分散を正規化**する（設計意図）。
- **手法の修正点**:
  - 測る対象を明確化して**3つを分離**して出す：
    1. `F_θ`（前処理前の生出力）ノルム、
    2. `D_θ = x̂₀`（後処理済み）ノルム、
    3. スコア `s = (D_θ − x)/σ²`。
  - **次元規格化**: `‖·‖/√d` を報告し、`d` を明記。「√d±1/√2 に一致するか」を**明示的にチェックし、一致するなら『正規化されている（=設計どおり）』と結論できるが、それはモデルの働きではなく前処理の帰結だと注記**する。
  - **入力依存性テスト**: 1108callでのCVを報告し、「異なる状態でどれだけ変動するか」を主眼にする。CV≈0 は「preconditioningが強力」ではなく「測度集中」であることを式で示す。
  - **std固定バグ検出**: 5ステップの std が有効数字4桁で一致した場合、**同一バッファ使い回しの回帰テスト**（各ステップのテンソルid/ハッシュが異なることをassert）を通す。
- **成果物**: `precond_norms_{Ftheta,Dtheta,score}.png`, `precond_normalized_by_sqrt_d.json`。
- **合否ゲート**: 「preconditioning正常」と書くのは、規格化前 `F_θ` の分散がσに対して意図どおり補正されていることを示せたときのみ。√d張り付きだけを根拠にしない。

### 3.D 有効ランク（k=4急崩壊の切り分け）

- **仮説 H_D**: 中間層（Block-4/9/13）は最終ステップで表現を低ランク化（特化）する。
- **バグ切り分け（最優先）**:
  - **捕捉同一性テスト T5**: k=0〜4 で「同じフック点・同じテンソル定義」から特徴を取っていることをassert（最終ステップだけ別テンソルを掴んでいないか）。x_k の σ_k 条件と feature の対応表を出力。
  - **段階監視**: PR を k の連続量として細かく（可能なら中間σも挿入して）追い、「崖」が離散化アーティファクトか真の相転移かを判定。
- **手法の修正点**: PR に加え、**同一の共分散から** cumulative-variance曲線・上位固有値スペクトルを併載（既にあるが、PRと同一run・同一プールで整合させる）。母集団（call間共分散か、token間か）を明記。
- **統計**: PR を episode ブートストラップし、k=3→4 の低下に CI。
- **成果物**: `effrank_by_k.png`(CI), `effrank_capture_consistency.json`。
- **合否ゲート**: 捕捉同一性テスト合格 かつ CKA急落（§3.K）・cos方向転換（§3.E）と符号一致を確認して初めて「真の再編」と記述。

### 3.E 特徴ノルム・方向（層別ダイナミクス）

- **手法の修正点**: ノルム推移・step間cosを維持しつつ、**§3.A・§3.D・§3.K と同一runの同一プール**で計算し、`‖Δfeat‖ ≈ √(‖a‖²+‖b‖²−2‖a‖‖b‖cos)` の**整合検算を自動テスト化**（レビューで手検算した233.3/76.13の一致を回帰テストに昇格）。
- **成果物**: `feat_norm_cos_by_k.png`, `feat_consistency_check.json`(検算残差)。
- **合否ゲート**: 検算残差が数値誤差内であること。

### 3.F 次元分解（XYZ/回転/グリッパー）

- **手法の修正点**: 群ごとの L2 を**次元数で規格化**（per-dim RMS 変化）して比較する。位置3次元・回転3次元・グリッパー1次元を同一土俵に。
- 空間オフセットの mean≈0 主張は、**episode ブートストラップCIが0を含むか**で判定（現状は目視）。グリッパーの大std は二値切替由来という説明を、実際に切替イベントを除いた条件付きstdで裏取り。
- **成果物**: `dim_change_perdim.png`, `dim_offset_ci.json`。

### 3.G 線形プロービング（リーク除去・分類器明確化・results_02↔03 の乖離解消）

これがレビュー最大の統計問題。**単一の統一プロトコル**に一本化し、全ファイルで共有する。

- **リーク除去（P3）**: PCA(2048→50)・標準化・クラス重み・閾値の**全前処理を LOEO の各fold内 train のみで推定**し、testに適用。Global PCA は廃止。
- **分類器の明確化**: 「Ridge回帰」を廃し、**多クラスは `LogisticRegression`（L2, one-vs-rest, class_weight='balanced'）を既定**とする。順序性を仮定しない。（線形プローブの趣旨は保つ。）
- **ラベル定義の統一と両論併記**:
  - `progress_3`: quantile分割で定義を統一（全ファイル共通）。
  - `gripper_2`: **物理的に意味のある閾値（開/閉境界）を主指標**とし、中央値閾値は「バランス版」として副次的に併記。両方の精度を出し、どちらの主張かを明記。
- **results_02↔results_03 乖離の強制照合（新規テスト T6）**: 「action トークン × progress_3(=call_idx thirds) × 全7層」を**同一runの同一コードパスで一度だけ計算**し、両レポートはその単一の表を参照する。0.72 と 0.50 のような乖離が出たら、**ラベル定義差／PCA有無／run差のどれで説明できるかを分解した表**を必ず添付（説明不能なら実装バグとして起票）。
- **統計（P4）**:
  - **permutation検定**: ラベルを episode 単位でシャッフルしてヌル分布を作り、各(層,k,ラベル)の精度が有意にチャンス超過かを p 値化。
  - **多重比較補正**: 7層×5ステップ×3ラベルに Benjamini–Hochberg（FDR）。
  - 精度は episode CV の平均±95%CI。0.44 と 0.50 の差を語るなら差の有意性も出す。
- **成果物**: `probe_acc_ci.json`(CI・p・FDR), `probe_perm_null.png`, `probe_reconcile_02_vs_03.json`。
- **合否ゲート**: 「層Xが高精度」はFDR補正後に有意なときのみ。results_02↔03 が照合表で説明できること。

### 3.H 言語クロスアテンション（near-uniform 問題）

- **仮説 H_H**: 深い層ほど実トークン上で選択的に言語条件に注目する。
- **手法の修正点（P8）**:
  - **padマスク後**に重みを正規化（§2.2）。実15トークン上で再正規化した分布を主対象に。
  - **一様ヌルとの効果量**: 各Top-k重みを「一様値 1/n_real」に対する比・および KL(attn‖uniform) で報告。**一様と統計的に区別できない層の『Top-3トークン物語』は書かない**（Block-0 の 1.4×一様のような読み取りを禁止）。
  - 集中度は **H_real と、一様帰無に対する permutation p 値**の両方で判定。
- **統計**: call をブートストラップし、H_real・KL に CI。層間の集中度差を検定。
- **成果物**: `crossattn_masked_topk.png`, `crossattn_vs_uniform_effectsize.json`。
- **合否ゲート**: 一様ヌルに対し有意な層のみトークン選好を主張。**このrunが成功率ゲート(§1.2)を通っていること**が前提。

### 3.I 自己注意（T位置別／空間）

- **前提**: §1.2 成功率ゲート必須。0%runでは実施しない。
- **手法の修正点**:
  - 11×11行列の値が「空間平均後の per-patch 値」であることを明記し、**行和1に正規化した版（T位置分布）を主指標**に切替（現状の0.00047系列は誤解を招く）。
  - 一様値 `1/STATE_T` を基準に、対角（自己注意）・モダリティ対応の**超過分を効果量**で示す。
  - 空間ヒートマップは CV(=std/mean) に**ブートストラップCI**を付け、「高CV/低CV」を有意差で語る。
- **成果物**: `selfattn_Tmatrix_rownorm.png`, `selfattn_modality_effectsize.json`。

### 3.J Attention Rollout（全層化 or 廃止）

- **問題**: 28ブロック中7ブロックのみ合成 → 累積推定として不正。かつ `0.5A+0.5I` で自己97.5%は構成上ほぼ自明。
- **選択肢（どちらか）**:
  - **J-a（全層化）**: 全28ブロックの実効注意を取得して正しく合成する。プローブ点だけでなく全層。
  - **J-b（廃止＋代替）**: Rolloutを落とし、**residual寄与を明示的に測る指標**に置換（例：各ブロックの `‖attn出力‖/‖residual‖` 比の層別プロファイル）。
- **ヌル B_J**: `A=I`（注意ゼロ）の rollout を基準に、実測が有意に自己参照から離れる量を示す。**「自己97.5%」は残差構造の帰結でありモデルの発見ではない**旨を数式で明記。
- **合否ゲート**: 部分層Rolloutでの累積フロー主張は禁止。全層化できないなら J-b を採用。

### 3.K 層間 CKA（action↔future_primary 等）

- **整合**: CKA急落・PR崩壊・cos方向転換が**同一run・同一遷移**で符号一致することを1枚の統合図で提示。

## 4. 統計的検定の共通枠組み（P4 の実装詳細）

| 項目 | 規定 |
|------|------|
| 独立単位 | **episode**（callではない）。同一episode内callは相関するため、必ずepisode単位でブートストラップ／シャッフル。 |
| 不確実性 | クラスタ（episode）ブートストラップ 1000反復で95%CI。 |
| ヌル検定 | ラベル・時系列を破壊した permutation を1000反復し p 値化。 |
| 多重比較 | Benjamini–Hochberg（FDR 0.05）。層×ステップ×ラベルの格子に適用。 |
| 効果量 | 平均差だけでなく Cohen's d / 一様比 / KL を併記。 |
| 検出力 | 「差なし／不成立」を主張する場合は、検出可能だった最小効果量を明記（無検出と真の無効果を区別）。 |
| 複数シード | 少なくとも3シードで主要指標を再現し、seed間分散を報告。 |
